# 냉장고 홈을 유지한 레시피·기록·내 부엌 수정

사용자는 현재 냉장고 홈을 이전 결과보다 낫다고 평가했고, 레시피·기록·내 부엌에 들어가면 비율이 무너지고 기능 연결도 확신할 수 없다고 지적했다. 이번 범위는 홈의 장면을 유지하면서 세 탭과 연결 상세 화면의 비율·조작·실제 저장을 고치는 것이다. 이전 시안/검사 결과를 사용자 디자인 승인으로 취급하지 않는다.

## 수정

- 네 메인 탭의 바깥 프레임과 하단 메뉴를 동일하게 유지한다. 320×568에서320×342.8, 390×844에서390×397.1, 801×782에서720×733.1이다. 사진을 가로로 늘리거나 글씨 전체를 축소해 맞추지 않는다. 대화상자는 최대560px 너비의 별도 읽기 공간을 쓴다.
- 레시피는 한 요리 카드와 이전/다음·전체 목록으로 탐색하고 필터는 별도 화면에서 조정한다. 휴대폰에서는 사진/정보를 좌우로, 넓은 화면에서는 위아래로 놓는다. 원본 접시 구도를 유지한다. 내 식단은 날짜·아침/점심/저녁 탭·계획별 페이지로 구성하며 저장·수정한 계획이 있는 끼니와 페이지로 이동한다.
- 실제 식사 입력은 먹은 양/재고 확인/이름·영양값 탭으로 나눈다. 같은 form의 표시만 바꾸므로 날짜·수량·체크·수정 영양값은 유지된다. 저장 버튼은 고정한다. 숨긴 패널에 잘못 입력한 필수 값이 있으면 해당 탭을 연다. 빠른 두 번째 물리 클릭이 완료 화면의 새 버튼을 눌러버리던 문제를 막는다.
- 기록은 영양/영양제/월간/식비를 유지하며 식사·제품·구매 내역은 페이지로 접근한다. 달력과 선택일 기록, 식비 요약과 구매 내역은 지역 탭으로 전환한다. 목표·기록 관리에는 수정/취소/직접 입력이 남아 있다. 새로 저장·수정한 식사를 바로 선택하고, 직접 입력의 선택 날짜와 예산 관리의 선택 월을 다음 화면에 전달한다.
- 내 부엌은 실제 선택 목표와 진행도를 표시한다. 첫 식사 보상·도감·소품 선택·배치·취소/적용을 유지한다. 편집과 적용 후 장면은 동일한2:1 투영과 소품 좌표를 사용한다. 큰 화면의620px 레거시 너비가 장면을 잘라버리던 문제와 작은 화면에서 도감 목표/기존 소품/백업 접근이 가려지던 문제를 고친다.

새 화면 모듈 세 개는 표시와 임시 탐색 상태만 담당한다. 기존 거래 모델과 `miniature-kitchen-preview-v1` 키, version1 및 재고·계획·식사·지출·소품 원문을 보존한다. 새 자산 생성·해상도 축소·예시 데이터 자동 주입은 없다.

## 저장 범위

일반 원본 HTML은 해당 브라우저 localStorage에 기록한다. 공유 HTMLPreview 래퍼는 opaque sandbox로 실행되어 `temporary` 상태이며, 새로고침 후 기록 유지가 보장되지 않는다. 공유 미리보기를 영구 저장 앱으로 보고하지 않는다. 내 부엌의 설정·백업에 상태와 내보내기를 표시하며, 임시 세션의 계획/식사/구매 입력 제목에도 작은 임시 미리보기 표시를 붙이고, 제목을 숨기는 식사 완료 화면에는 본문에 임시 기록·백업 안내를 표시한다. 공용 미리보기 원점에 기록을 노출할 수 있는 allow-same-origin 추가로 이를 우회하지 않는다.

## 검증

같은 격리 검토 자료·날짜·뷰포트로 변경 전후 실제 화면을 비교한다. 메인에는 문서 스크롤 없이 핵심 조작을 유지한다. 많은 영양 필드·긴 구매 목록·백업 등의 상세에는 내부 스크롤이 남는다. Chromium의320/390/801 검사와 실제 Safari/Notion 기기 확인은 구분한다. main/Pages는 이번 작업에서 변경하지 않는다.

[변경 전후 실제 화면](kitchen-tabs-20261105/tabs-before-after.png), [수정한 세 탭](kitchen-tabs-20261105/tabs-after.png), [네 메인 프레임 비교](kitchen-tabs-20261105/main-frame-comparison.json)를 기록했다. 동일한 격리 자료와 날짜를 사용했으며 A1의 장면/재료/메뉴 위치와 바깥 크기를 유지했다. PNG 전체 바이트가 같다는 주장은 하지 않는다.

[기능 기준 빌드의 레시피 검사](kitchen-tabs-20261105/functional-recipes.json)는 native30/wrapper12 그룹, [기록 검사](kitchen-tabs-20261105/functional-records.json)는 native/wrapper320·390·801의 날짜·월 전달/새 식사 선택/수정·취소/복용/실제 지출·재고 분리와 누락 값·다중 제품의45그룹을 통과했다. [성장 목표](kitchen-tabs-20261105/growth-goals.json), [보상·취소·적용](kitchen-tabs-20261105/growth-transactions.json), [장면 투영](kitchen-tabs-20261105/growth-projection.json), [설정·백업 접근](kitchen-tabs-20261105/kitchen-backup-access.json)은 별도 고정 후보3에서 확인했다. 이 보고서들의 당시 입력 해시는 보존한다.

기능 기준 이후에는 B1 탄단지 값을 복원하고 B2의 사진/하단 여백을 조정했다. [최종 관계 증명](kitchen-tabs-20261105/final-build-relationship.json)에서 최종15개 스크립트와 모든 AVIF가 기능 기준과 같고 레시피 스타일1개만 달라졌음을 확인했다. [최종 B1/B2 실제 검사](kitchen-tabs-20261105/final-recipe-visual.json)는 세 폭×8요리24카드의 탄단지(미입력 포함), 기본5재료 전체,46px 두CTA 및 지역 스크롤0을 확인했다. 기능 검사 통과를 외형 승인으로 대신하지 않는다.

[저장소 검사](kitchen-tabs-20261105/validation.json)는 Python274/Node233/전송12·일곱 JS 문법·diff검사를 통과했다. [생성물4개](kitchen-tabs-20261105/generated-files.json)는 각각1MiB 이하이며 포장을 풀면 생성 원문과 같다. 공개 URL과 해당 고정 소스의 브라우저 실행은 별도로 확인한다.
