# 문을 닫을 때 빈 패널이 보이는 문제 · 2026-10-29

사용자 화면에서 열린 왼쪽 칸과 닫는 오른쪽 문의 빈 표시창을 확인했다. 기준은 `c0832689`다. 기존 코드는 문이 움직이는 동안 외부의 선명한 LCD를 숨겼고, 문 그림 자체에는 작은 빈 패널만 있었다. 그 결과 닫는 도중에 원본 그림의 빈 패널이 드러났다.

로컬 Chromium의 앱·위젯과 공개 확인용 프레임에서 이 중간 화면을 재현했다. 정상 종료 시에는 표시창이 돌아왔으므로 **닫힌 뒤 영구적으로 돌아오지 않는 상태까지 재현됐다고 단정하지 않는다.** 이전 검사의 많은 조건이 애니메이션 감소 설정을 사용해 이 구간을 놓친 점도 구분한다.

## 수정

문이 움직이는 동안 같은 정보·같은 배치의 표시 사본을 문 앞면에 붙인다. 문 그림과 함께 회전하므로 빈 패널이 노출되지 않는다. 정상 닫힘과 650ms 복구 경로 뒤에는 사본을 제거하고 기존의 실제 픽셀 크기 LCD로 돌아온다. 닫힌 상태의 디자인·좌표·글자 렌더링은 유지한다.

사본은 닫힌 Shadow DOM 안에 두어 SVG 자르기 ID와 일반 UI 선택자를 분리한다. 접근성 트리·초점·터치 대상에서 제외하며 문 버튼 조작을 유지한다. 움직이는 면에서는 뒤쪽 블러를 다시 계산하지 않는다. 저장 키·자료 형식·재료/영양 계산과 기존 앱 데이터는 바꾸지 않았다.

## 검증

새 [브라우저 회귀](../scripts/test_kitchen_door_displays_browser.py)는 실제 CSS 애니메이션을 실행한다. 기준 버전에서는 움직이는 문의 빈 화면 검사에 실패하며, 수정본의 12가지 조건은 통과했다.

- 앱·위젯, 일반 화면/독립 출처 프레임, 649×900·390×660, 320×568과 애니메이션 감소 설정을 확인했다.
- 양쪽 문을 닫는 실제 CSS 전환을 약 78% 위치에 멈추고 화면 픽셀을 검사했다. 어두운 표시창 면과 오른쪽 민트색 원이 그려졌는지 확인하므로 빈 사본 상자만으로 통과하지 않는다. 캡처 중 복구 타이머가 먼저 실행되지 않았는지도 검사한다.
- 완전히 닫힌 뒤 기본 LCD의 표시와 변환 없는 글자 계층, 빠른 방향 전환, 종료 이벤트 차단, 전환 취소 시의 복구, 중복 사본 제거와 기록 보존을 확인했다.
- 기존 장면·이동·저장 회귀 111개, 식사·영양·도감 회귀 13개도 통과했다. 원본/작은 내장형 UI 코드 일치, 1MiB 이하 공개 파일, 구문·diff를 확인했다.

이 회귀의 문 활성화는 애니메이션과 화면 복원을 따로 검증하기 위해 DOM 버튼 클릭으로 실행한다. 이전에 기록한 공개 프레임의 간헐적인 실제 터치 전달 문제를 해결했다고 해석하지 않는다. 실제 iPhone/Safari·Notion·외부 렌더러 새 주소 실행은 미확인이다. [검사 기록](miniature-kitchen/door-return-validation.json)을 따른다.

```bash
source /workspace/.notion-cloud/activate.sh
python scripts/test_kitchen_door_displays_browser.py \
  --root previews --mobile-root previews/mobile \
  --output /tmp/notion-door-displays
```

작업 브랜치의 앱·위젯 미리보기를 갱신한다. main·Pages는 배포하지 않았고, 기존 PR API의 403 차단 상태와 비교 경로는 [앞선 검토 기록](APPROVED_KITCHEN_CONCEPT_2026-10-29.md)을 따른다.
