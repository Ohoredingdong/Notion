# 투자 타이밍 유용성 확인·알림 계약

정책 버전: timing-utility-acceptance-1.0
작성일: 2026-10-29 (Asia/Seoul)
상태: 향후 개선 실험과 사용자 알림의 검수 기준. 이 문서의 저장은 모델 변경, 유용성 입증, 실시간 연결 또는 실거래 승인이 아니다.

## 사용자 요청

타이밍 판단에 실제 도움이 될 때까지 개선·시험·검토를 수행하되, 일상적인 진행 보고와 같은 경고를 반복하지 않는다. 완료 알림은 아래 조건을 실제 증거로 충족한 범위에서만 발행한다. 모든 가격 움직임을 맞힌다는 보장이나 완료 기한은 설정하지 않는다. 일부 범위의 성공을 전체 종목·전체 시장·모든 시점의 성공으로 확장하지 않는다.

## 단계 구분

- 연구 후보: 구현·단위검사·과거 분리 검증을 통과한 실험. 사용자 완료 알림 대상 아님.
- 방향 성능 검증: 사전 발행한 이후 결과에서 양방향 우위 확인. 이것만으로 매매 타이밍 유용성을 승인하지 않음.
- 제한된 타이밍 유용성 확인: 방향 성능, 전달시점, 체결가능성, 비용 후 실익, 위험, 독립 후속 검증을 모두 확인한 시장·종목·시간구간에 한정해 알림.

## 반드시 충족할 조건

1. 사전 기록과 자료 무결성
   같은 commit의 ledger, outcomes, deliveries, attempts, learning state/report를 읽는다. 실제 관측·수신·발행·최초 공개·알림 전달·결과 확인 시각을 분리한다. 최초 방향·확률·판정 폭·대상 구간을 보존한다. 미래 자료 혼입, 소급 발행, 중복 사건, 겹친 표본, 누락·보류를 별도 집계한다. 공개 웹 응답은 사용자 푸시 수신이 아니다. 저장된 결과 계산 검사와 원시 가격의 외부 대조는 다른 검증이다. 필요한 원시자료와 적법한 이용 권한이 없으면 미확인이다.

2. 실제 미래의 양방향 성능
   docs/stock-direction-specialists.md의 기존 사전 교체 문턱을 완화하지 않는다. 그룹별 최소 120개 비중첩 타깃, 20개 관측일, 각 실제 방향 10개, 상승·하락 예측 각 10개와 기존 방향별 포착·정밀도·균형 정확도·확률오차 개선 조건을 기본 최소로 유지한다. 전체 정확도뿐 아니라 상승·하락별 놓침, 거짓신호, 보류율, 확률 보정을 평가한다. 사전에 고정한 단순 빈도·항상 횡보 등의 비교 기준과 동일 사건에서 대조한다. 없던 과거 기준 확률을 소급 생성하지 않는다. 이 숫자는 운영정책이지 통계적 증명이나 충분한 검증의 보장이 아니다.

3. 행동 가능한 시점과 비용 후 실익
   주문 없는 전향적 모의 검증에서 신호가 행동 가능한 시간에 전달되었는지 확인한다. 사전에 고정한 진입·취소·위험회피·청산 규칙, 신호 지연, 당시 실제 매수/매도 호가, 거래수수료·관련 세금·스프레드·슬리피지를 기록한다. 공짜 체결, 과거 종가 진입, 미체결 주문의 체결, 공매도 가능성을 가정하지 않는다. 자료를 확보하지 못한 비용이나 호가는 보수적인 가정·민감도 분석과 미확인을 분리하며 실측값으로 표시하지 않는다. 같은 대상·기간·자금 및 위험 기준의 사전 비교전략보다 비용 후 기대손익이 우월하고, 하방위험·최대낙폭이 사전 위험 한도 내인지 확인한다. 평균 적중률이 높아도 이 조건이 확인되지 않으면 타이밍 유용성 완료 알림을 보내지 않는다. 실제 돈을 투입하거나 주문하지 않는다.

4. 선택에 쓰지 않은 후속 구간과 독립 감사
   실험별 가설·모델·피처·정책·데이터 가용시점과 시험 횟수를 남긴다. 교체 선정에 쓴 구간을 최종 확인 구간으로 재사용하지 않는다. 변경 전에 별도 후속 검증 범위·종료 조건·비교 방법을 고정하고 새 구간에서 우위가 유지되는지 확인한다. 반복검정·종목 간 상관·국면 의존·생존편향을 고려한다. 여러 번 시험하다 우연히 좋은 순간에 중단한 결과를 증명이라 부르지 않는다. 과거자료의 당시 버전이 없으면 point-in-time 검증이라고 하지 않는다. 모델 코드와 분리된 감사가 증거와 계산을 재현해야 한다.

5. 실제 작동과 안전 통제
   수집, 학습, 평가, 공개 배포 및 필요한 알림 경로의 실제 성공을 확인한다. GitHub 예약 실행을 연속 실시간 감시로 부르지 않는다. 토스 인증·고정 IP·상시 서버는 실제 연결 증거가 있어야 연결 상태로 표시한다. 이미 인증된 OpenDART와 혼동하지 않는다. strict-green-1.0의 12개 검사·실사 원문·독립 가치평가·가격/EPS/기간/fingerprint 정합성을 그대로 유지한다. 연구 성능 통과는 기업 매수 승인과 별개다. 키, 토큰, 인증 요청 URL, 계좌 개인정보를 공개하지 않는다.

## 개선 작업 규칙

예약 실행에서 사용 가능한 도구로 실제 분석과 재현 검사를 수행한다. 원인이 확인된 문제가 있으면 작은 변경을 연구 브랜치에서 시험하고 회귀검사를 붙인다. 새 모델/피처는 shadow 후보로만 추가하고 사전 정책 검증 없이 운영 신호로 승격하지 않는다. 비교·시험·변경 내용은 기존 파일을 먼저 확인해 중복 없는 실험 기록으로 남긴다. CI와 독립 감사, 필요한 화면·배포 검사를 실제 통과한 변경만 연구 파이프라인에 반영한다. 통과하지 못하면 PR/실험 기록에 남기고 정상 버전을 보존한다. 기존 원자료·정답·예측 원장·오답·과거 시각은 덮어쓰지 않는다. 판단 기준을 결과에 맞춰 낮추거나 매번 새 후보를 무제한 탐색하지 않는다. 같은 장애의 열린 PR이 있으면 새 PR을 반복 생성하지 않는다. 관련 없는 파일·다른 예약·계정 설정을 변경하지 않는다. 유료 서비스, API/계좌 인증, 고정 IP 서버 계약은 사용자 없이 진행하지 않는다.

## 사용자 알림

통상적인 테스트 통과·새 표본·일시적 개선·오류 수정 보고는 보내지 않는다. 조건을 처음 충족했을 때만 검증 범위, 원기록/commit, 표본수·기간, 상승/하락 성적과 거짓신호, 제공률, 비용 후 비교 결과·위험, 전달시각, 독립 검사 근거, 남은 한계를 한국어로 보고한다. '완벽', '100% 보장', '모든 움직임 적중'이라고 선언하지 않는다.

필수 인증/권한/자료를 사용자가 제공해야 진행할 수 있는데 새로운 조치가 필요한 경우에는 막힌 항목을 한 번만 알린다. 이미 알려진 토스 미연결을 반복 통지하지 않는다. 확인된 유용성 판정이 이후 무효화되거나 실제 사용에 위험한 새 오류가 생긴 경우에는 철회/위험 경고를 허용한다. 나머지는 조용히 기록한다.
