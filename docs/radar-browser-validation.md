# 투자 레이더 개발용 브라우저 검증

`scripts/test_radar_development_browser.py`는 정적 서버에서 **실제 저장 JSON**을 읽고 투자 레이더를 검사합니다. 수집기·게시기·외부 API를 실행하거나 금융 데이터를 수정하지 않습니다. 브라우저는 매번 새 임시 컨텍스트를 사용하며 기존 개인 프로필에 접근하지 않습니다.

```sh
# 별도 터미널, 저장소 루트
python -m http.server 8766 --bind 127.0.0.1

# Playwright의 설치된 Chromium을 사용하는 CI
python scripts/test_radar_development_browser.py \
  --base-url http://127.0.0.1:8766/ \
  --artifacts /tmp/radar-after

# 이 클라우드 환경의 기본 제공 Chromium을 쓰는 경우
python scripts/test_radar_development_browser.py \
  --base-url http://127.0.0.1:8766/ \
  --executable /usr/bin/chromium \
  --artifacts /tmp/radar-after \
  --baseline-dir /tmp/radar-before
```

`--base-url`은 HTML 파일 주소가 아닌 정적 서버의 루트 주소입니다. 별도 브라우저 경로를 생략하면 설치한 Playwright 버전의 브라우저를 사용합니다. 로컬 실행 환경의 소켓·프로세스 제한으로 실행이 거부되면 지원되는 실행 승인 절차를 사용하며 프록시나 TLS 검증을 해제하지 않습니다.

## 실제로 검사하는 항목

1. 데스크톱 1366×768: 호환 URL의 종목·해시 보존, 저장 원자료와 표시 종가·기준일 일치, 가격 차트, 종목 선택과 상세 화면의 티커, 상세 버튼을 가리는 겹침 여부와 하단 안내까지 한 화면에 보이는지, 관심종목과 선택·무관한 사용자 기록의 새로고침 후 보존.
2. 모바일 390×844: 가로 넘침, 저장 종가 표시, 상세 화면 이동.
3. 임베드 900×650: sandbox가 있는 iframe에서 실제 앱을 열고 가로 넘침과 상세 이동 확인.
4. 갱신 실패: 한 번 정상 데이터를 읽은 뒤 원자료 요청만 의도적으로 끊고 기존 정상 원자료·종가·목록이 유지되며 실패 안내가 나타나는지 확인.
5. 초기 로딩 실패: 처음부터 원자료를 읽을 수 없으면 임의의 기업·종가·목록을 만들지 않고 이용 불가를 표시하는지 확인.

오류 주입은 격리된 테스트 컨텍스트의 요청 차단으로만 수행합니다. 실제 네트워크 서비스의 장애라고 보고하거나 테스트 입력을 운영 데이터에 기록하지 않습니다. 페이지 스크립트의 처리되지 않은 예외가 있거나 5개 시나리오가 모두 실행되지 않으면 실패로 종료합니다.

## 수정 전후 화면 증거

수정 전 `--artifacts /tmp/radar-before`로 실행하고 수정 후에는 다른 출력 디렉터리와 `--baseline-dir /tmp/radar-before`를 지정합니다. 이전 결과를 덮어쓰지 않습니다.

- `report.json`: 현재 실행 ID, 커밋, 브라우저 버전, 실제 제공된 HTML·스크립트·데이터 지문과 수집 시각, 시나리오별 실행·실패·단언 수, 화면 크기와 스크린샷 경로.
- 실행 ID 하위의 PNG: 홈·목록·상세·모바일·임베드·실패 처리 화면.
- `visual-comparison.html`: 동일한 화면 이름의 수정 전후 이미지를 나란히 보는 문서.

알려진 버그 때문에 수정 전 검사가 실패했어도 실패 결과와 남아 있는 이미지를 보존합니다. 이 경우 `baseline_functional_pass: false`와 누락된 이전 이미지를 명시합니다. 수정 후 기능 검사 성공과 화면의 시각적 승인은 별도입니다. 스크린샷 바이트 차이는 시간·데이터·브라우저·디자인 변경 모두에서 생길 수 있으므로 **시각적 검토를 자동 통과로 처리하지 않습니다**. 실행 결과의 `approved`는 항상 `false`이며 사람이 실제 이미지를 비교해야 합니다.

임베드 검사는 로컬의 Notion 유사 환경입니다. 실제 Notion 제품 UI·현재 헤더 정책, 운영 사이트 배포 상태, 실시간 제공처의 데이터 신선도와 예측 정확도는 이 검사만으로 검증되지 않습니다.

## 기존 검사와의 관계

기존 `test_stock_radar_canonical_browser.py` 및 `test_stock_radar_flow_browser.py`도 유지합니다. 현재 승인된 런타임 6개, 심리지수 v9, 상세 화면 v6를 기준으로 오래된 테스트 선택자와 고정 날짜를 수정했으며, 검색은 실제 종목명·코드 부분일치 동작을 검증합니다. 실제 버튼 겹침은 테스트를 강제 클릭으로 우회하지 않고 CSS의 grid 축소 원인을 수정했습니다.
