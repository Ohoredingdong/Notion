# 추가 비율 점검과 활용 안내

2026-11-05, 개발 체계 브랜치 `0e46462d`를 기준으로 실제 브라우저에서 남아 있던 비율 문제를 확인하고 수정했습니다. 이 작업은 작업 브랜치의 변경이며 운영 배포를 의미하지 않습니다.

| 확인한 문제 | 수정 전 | 수정 후 |
|---|---|---|
| 경매노트 390×844: 긴 현금 금액만 두 줄로 꺾여 다른 카드와 불균형 | [전](auction-mobile-before.png) | [후](auction-mobile-after.png) |
| 레이더 900×650: 지수 숫자와 미니 차트의 실제 글자가 겹침 | [전](radar-iframe-before.png) | [후](radar-iframe-after.png) |

경매노트는 첫 현금 카드를 전체 너비의 작은 가로 카드로 바꾸어 금액을 한 줄·27px로 표시하고, 손익·권리 확인 두 카드의 크기와 숫자 기준선을 맞췄습니다. 390×667에서도 페이지 전체 스크롤을 만들지 않습니다. 저장 제한 안내가 나타나는 iframe에서는 검토 순서 행이 겹치던 문제를 최소 행 높이와 패널 내부 이동으로 해결하며 안내문과 마지막 버튼을 보존합니다.

레이더는 851–1179px에서 숫자 아래에 등락률·미니 차트 공간을 따로 두었습니다. 숫자·출처 날짜·차트를 숨기지 않으며 기존 데스크톱·모바일과 종목 분석 버튼 배치를 보존합니다. 기존 금융 원본은 바꾸지 않았습니다.

실제 캡처와 글자 범위 기반 검사를 함께 사용했습니다. 경매 기존 8개와 추가 iframe 검사까지 9개 시나리오, 레이더 5개 시나리오의 199개 검사, 850/851/1179/1180px 경계의 152개 검사를 확인했습니다. 실제 Notion UI·공개 사이트·미래의 모든 글꼴과 화면을 확인한 것으로 표시하지 않습니다. 851px 부근 기존 재무 지표의 값·단위 줄바꿈은 유지되며 자동 검사의 통과를 모든 디자인의 승인으로 해석하지 않습니다.

앞으로 개발 요청은 [사용자 활용 방법](../development-workflow.md#사용자가-활용하는-방법)을 따릅니다. 현재 대화에서는 변경할 화면과 원하는 동작을 자연어로 요청하면 되고, 새 Codex 작업은 이 개발 체계 브랜치를 기준으로 시작합니다. main에 승인·병합되기 전에는 main이나 공개 사이트에 이 변경이 자동으로 적용됐다고 보지 않습니다.
