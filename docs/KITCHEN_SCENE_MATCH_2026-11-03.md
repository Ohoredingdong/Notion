# 큰 화면 구성과 재료 표현 수정

사용자는 801×782 실제 위젯 스크린샷으로 앞선 결과가 시안과 다르다고 다시 지적했다. 앞선 390px의 몸체 크기 측정과 기능 통과를 시각적 일치로 평가한 것은 잘못이었다. 이번 검토는 사용자가 보낸 화면 크기와 실제 임시 세션을 포함한다.

주요 원인은 서로 다른 확대 기준이었다. 720px 위젯에서도 상단은 약 98px, 하단은 48px로 남은 반면 몸체는 421×496px까지 커졌다. 메인 구도를 390px 기준으로 함께 확대하도록 바꿨다. 새 801×782 화면에서는 몸체 약 368×433px, 상단 약 180px, 하단 약 88px이며 창문·식물·조리대가 드러난다. 이 숫자를 시안과 동일하다는 판정에 쓰지 않는다.

- 재료 그림은 선반·서랍보다 작게 표시한다. 투명한 44px 조작 영역이 커져도 그림 자체가 커지지 않도록 분리했다. 우유·작은 보관통·대파의 높이와 바닥 위치를 달리한다. 냉동 앞유리는 그림보다 앞 레이어에서 표시한다.
- 처음 비어 있는 미리보기에 사용하는 기존 8개 냉장 재료를 작은 두 열과 세로 우유로 재배치했다. 재료·수량·기한·ID·냉동 5개·양념 4개를 추가하거나 삭제하지 않는다. 기존 v1 자료를 읽으면 원래 세계·좌표·기록이 복원되며 이 초기 배치로 이전하지 않는다.
- 문 각도는 110도다. 추가 버튼은 전체 위젯 오른쪽에 붙여 작은 `.room` 기준으로 안쪽에 들어오던 문제와 냉동 채소 가림을 해결했다.
- 문 열고 닫기는 접근성 알림만 유지한다. 저장/적용 알림은 계속 표시한다. 기한 라벨은 음식 앞쪽으로 내려 작은 사진을 가리지 않게 한다. 입력이 없는 날에도 탄단지 종류의 색상 표시는 유지하며 숫자를 만들어 넣지 않는다.
- 작은 화면의 투명 조작 영역이 겹치는 경우 실제 그림 아래의 재료로 포인터를 연결한다. 단순 `elementFromPoint`의 위쪽 버튼 ID 대신, 실제 클릭 뒤 올바른 A6 재료 ID가 열리고 데이터가 바뀌지 않는지를 검사한다.

공유 소스는 `scene.js`, `scene.html`, 새 `scene-occupancy.css`, `scene-composition.css`다. 변형된 브로콜리 이미지와 미사용 아틀라스 실험은 전달물에 연결하지 않았다. 기존 이미지 해상도·품질, 저장 키/v1, 운영 HTML과 main/Pages는 유지한다. 네 전달 파일은 기존 1MiB 한도 내에서 생성한다.

시안의 약 60/40 냉장·냉동 분할과 현재 자산의 약 54/46 분할, 얕은 여러 식사 용기, 긴 잎채소, 통합된 조명은 여전히 다르다. 이번 결과는 크기 위계·구도·재료 표현을 고친 실제 실행 화면이며, 시안과 같은 그림이거나 사용자가 승인한 결과로 설명하지 않는다.

검사 원본과 중간 후보는 작업 폴더 `kitchen-scene-match-20261103`에 구분했다. 선택한 전후 화면·복원 검사·최종 공개 실행 증거는 `docs/kitchen-scene-match/`에 기록한다. 화면 크기 검사는 Chromium 실행이며 실기기·Safari·Notion·OCR 검증은 아니다.
