# Bounded autonomous research loop — 2026-10-29

This is executable research automation, not a promise of perfect predictions. It does not enable orders, alter strict-green approval, invent a Toss connection or change OpenDART credentials.

The forecast workflow now calls `stock_forecast_autopilot.py`: collect real OHLC with bounded recovery; train the reviewed challenger catalogue; freeze prospective estimates; score already-public forecasts against matured outcomes; update only new eligible answers; evaluate forward promotion/rollback gates; independently recheck arithmetic, chronology and immutable rows; publish one compare-and-swap bundle. Rejected stages do not overwrite the previous ledger or learning state. The UI distinguishes the last verified research run from predictive usefulness.

## What changes automatically

Learned weights and the applied research variant may change within the preregistered catalogue. One new recipe family is added: first estimate material movement versus flat, then estimate up versus down conditional on movement. It is calibrated on the separate chronological calibration segment and remains a shadow candidate until the same forward gates pass. Previous false predictions are never rewritten. Four challengers are now compared, so the comparison interval tail is tightened from 0.05/6 to 0.05/8. No old missing candidate probability is backfilled.

The program does not invent arbitrary new source code, lower acceptance thresholds or search infinitely many models until one happens to look perfect. The hourly assistant task may investigate additional engineering changes separately under the existing review-and-test contract; that is not proof that such a future change has run.

## Recovery

Per-source transient connection/timeout/cache-lock failures are retried once. A rate-limit response is not immediately retried; its cooldown is persisted in successful research bundles. All-source failure rejects the cycle; an uncommitted cooldown in a failed stage is not claimed to be persisted. Infrastructure deployment/dependency failures receive at most one GitHub rerun through `Stock Autopilot Bounded Recovery`. Test, model, state-integrity and audit failures are not blindly rerun. Failed rerun requests or exhausted retries remain failures, not successful recovery.

## Actual limits

The current input is delayed unofficial Yahoo history, not continuous live broker data. A statistical model can be retrained without becoming more accurate. The controller therefore reports timing usefulness as unproven: independent executable quote/notification evidence, after-cost timing validation and an untouched follow-up confirmation are not yet connected. The task's completion-notification contract remains in force; research-cycle success cannot emit a usefulness or perfection notification. Real-time authorization, server/IP provisioning and trading-data rights cannot be manufactured by a self-improvement loop.

## Verification

New synthetic fault-injection tests cover finite retries, rate-limit backoff, immutable evidence, failed-transaction rollback, duplicate/unauthorized learning and the new classifier. Existing forward-learning, direction and source tests remain. Branch runs execute the real pipeline but never publish their trial outputs to main. Only a reviewed branch that passed tests is merged, then public JSON and JavaScript bytes are checked separately. Test fixtures never become production prices.
