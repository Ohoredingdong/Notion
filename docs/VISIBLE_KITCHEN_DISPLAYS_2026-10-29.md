# 작은 화면의 디스플레이 요소 복구 · 2026-10-29

사용자 스크린샷처럼 왼쪽에 글자 두 행만, 오른쪽에 메뉴명과 작은 링만 남는 화면을 재현했다. 원인은 `e36e67e8`에서 폭 100px 미만 또는 높이 210px 미만인 표시창을 축소 구성으로 분류하고, 그 구성의 `.lcd-counters`와 `.lcd-dish`를 `display:none`으로 숨긴 것이다. 폰의 표시창은 대부분 이 조건에 들었고 약 100×200px인 창에서도 같은 문제가 생겼다. 재료 아이콘도 축소 구성에서 숨겨졌다. 자산 파일이 없거나 로딩에 실패한 현상과 구별한다.

## 수정

앱·위젯의 같은 CSS·템플릿에 적용했다. 약 100×200px 창은 오늘 원 → 내일/2~3일 타일 → 재료 3행·아이콘, 음식 그림 → 메뉴/조리 정보 → 기록률 원·미등록 재료로 표시한다. 이 크기에서 내부 여백과 보조 정보의 비율을 따로 맞췄다.

더 좁은 문에서도 오늘 원·실제 음식 그림·재료 기록률 원을 유지한다. 높이가 짧으면 실제 재료 행 수와 보조 설명을 줄이고, 가장 작은 320×568 화면은 음식 그림과 기록률 원을 같은 줄에 둔다. 전체 제목·메뉴 이름·표시 수량은 유지한다. 상단 확대 읽기는 그대로 제공하지만 기본 문 안의 핵심 그림을 대신하는 용도로 사용하지 않는다.

냉장고 본체·배경, 문과 LCD의 위치·크기, 저장 키·형식과 재료 계산은 변경하지 않았다. 표시 전용 높이 분류 속성과 보이는 행 수만 조정했다. 기존 문 조작과 식사·영양·도감·꾸밈은 유지한다.

## 확인

- 앱·위젯 × 12가지 화면 크기, 총 24조건에서 기존 8종 메뉴를 각각 렌더링했다. 제목·이름·수량·보이는 정보의 잘림을 검사하고 오늘 원과 기록률 원의 표시, 실제 음식 그림의 색상 픽셀을 확인했다. 빈 그림 프레임의 표시만으로 통과하지 않는다.
- 각 조건에서 양쪽 표시창을 실제 화면 좌표로 터치해 문을 열고 열린 문을 다시 눌러 닫았다. 장식이 터치를 가로채지 않는지, 기록·날짜·수량·최종 문 상태가 유지되는지 확인했다. 기존 문 개방 시 재료의 가로 경계 보정은 유지한다.
- 같은 예시 데이터·닫힌 문·시각 `2026-10-28T03:00:00Z`/Asia/Seoul의 전후 12쌍에서 본체와 표시창의 위치·크기가 모두 같다. 760×780 조건은 사용자 스크린샷과 같은 종류의 약 100×200px 표시창 문제를 재현한다. 스크린샷만으로 사용자의 실제 뷰포트가 이 크기였다고 단정하지 않는다.
- 실제 바탕 픽셀 대비 20상태 검사에서 최저 약 4.65:1이다. 실제 배경 투과와 투명도 감소 대체 스타일도 통과했다.
- 기존 식사·영양·도감·저장 회귀 13개 통과. 원본·작은 내장형의 UI 코드 일치, 1MiB 이하 공개 파일과 구문·diff를 확인했다. 전체 장면 111개 회귀는 이번에는 재실행하지 않았다.

[검사 기록](miniature-kitchen/visible-validation.json)을 따른다. 로컬 Chromium 결과이며 실제 iPhone/Safari·Notion·새 공개 렌더러 주소 실행의 검증이 아니다. 앞서 기록한 공개 샌드박스 프레임의 간헐 문 터치 오류는 이번 수정으로 해결됐다고 주장하지 않는다. main·Pages는 배포하지 않았으며 기존 PR API 403 차단과 검토 브랜치는 [이전 기록](APPROVED_KITCHEN_CONCEPT_2026-10-29.md)을 따른다.
