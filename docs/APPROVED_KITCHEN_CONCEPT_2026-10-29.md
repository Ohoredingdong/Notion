# 이미지 시안 01 적용 · 2026-10-29

> 후속 사용자 스크린샷에서 작은 화면의 핵심 요소 누락을 확인해 [표시 복구](VISIBLE_KITCHEN_DISPLAYS_2026-10-29.md)로 수정했다. 아래 축소·검증 설명은 최초 적용 기록이다.

사용자가 [이미지 시안 01](miniature-kitchen/approved-concept.png)을 확인한 뒤 “그래 그렇게 수정해봐”라고 요청했다. 기준 커밋은 `29bcfd99`다. 이미지의 시각 방향을 앱·위젯의 독립 조작 화면에 적용한다. 구현 결과의 최종 검수·main 배포·기존 앱 데이터 연결까지 승인됐다는 뜻은 아니다.

## 실제 변경

- 표시창을 위쪽 문의 높이 약 72%로 늘렸다. 왼쪽은 오늘 원형 건수 → 내일/2~3일 → 실제 임박 재료 3행 → 총 건수, 오른쪽은 큰 음식 그림 → 메뉴/조리 정보 → 민트색 이름 기록률 링 → 미등록 재료 순서다. 두 제목과 본문은 중앙 정렬한다.
- 차분한 회색 유리, 가는 실버 가장자리, 배경 투과와 뒤쪽 블러, 부드러운 반사를 사용한다. 글자는 3D·축척 변환 밖의 실제 픽셀 크기로 렌더링한다. 투명도 감소 설정에는 불투명 대체 스타일을 쓴다.
- `room-concept.png`는 기존 배경과 선택된 이미지 시안을 참고해 이미지 생성 도구로 만든 크림 타일·연한 오크 배경이다. 원본 `room-centered.png`를 보존한다. 기존 중앙 설치 공간·바닥선·선반 위치에 맞춰 합성하고 전후 화면을 확인했다.
- 휴대폰의 작은 문에는 실재 기록의 요약을 표시한다. 그림·기한별 타일·미등록 재료를 빽빽하게 축소하지 않는다. 아주 짧은 화면은 조리시간도 확대 화면에서 읽는다. 상단 **표시창 크게 보기**는 현재 기록의 같은 화면을 넓게 표시하며, 좁은 폰에서는 두 패널을 세로로 스크롤한다. 문이 열려 있어도 읽을 수 있고 닫으면 이전 버튼으로 초점이 돌아온다.

냉장고 본체와 문 그림, 손잡이·재료 아틀라스, 본체 중앙 좌표·크기·바닥선과 클릭/터치 영역은 유지했다. 이미지 속 본체·소품을 모두 그대로 재제작한 결과는 아니다. 열린 문을 다시 눌러 닫는 조작, 재료/양념 이동·기한 입력, 식사·영양·도감·꾸밈 기능을 유지한다. 새 상태나 저장 키는 추가하지 않는다. `miniature-kitchen-preview-v1`의 형식과 기존 앱 기록은 변경하지 않는다.

이름 기록률은 재료 이름의 일치 수이며 수량의 충분함·실제 조리 가능·영양 충족을 뜻하지 않는다. 기한 경과 재료는 기록률에서 제외하고 경과 경고를 유지한다. ‘2~3일’ 숫자는 오늘/내일과 겹치지 않는 실제 기록 건수다. 사진 인식·자동 영양/비용 계산·재고 차감은 이번 수정에 포함하지 않는다.

같은 예시 데이터·닫힌 문·고정 시각 `2026-10-28T03:00:00Z`/Asia/Seoul에서 앱·위젯 × 649×900·390×660·320×660·320×568 전후 8쌍을 비교했다. 본체의 위치·크기는 모두 같다. 표시창 좌표·높이와 배경 소재는 의도한 변경이다. 처음 확인한 작은 화면 겹침과 낮은 대비는 수정 후 다시 검사했다.

- 집중 검사 12개 묶음: 각각 11가지 화면 크기, 8종 메뉴, 경계·기한·수량·빈 상태·경과 양념·이름 기록률·직접 문 조작 통과.
- 확대 읽기 8가지 앱/위젯·화면 조건: 실제 값, 3행·원형 표시, 넘침, 문 상태 보존, 최신 수량·기한, 닫기·키보드 초점 통과.
- 원/막대 0·40·100% 픽셀 검사 6가지 조건 통과. 대비 검사 12가지 상태는 실제 반사·카드 바탕까지 렌더링한 글자 영역의 최저 대비 약 4.72:1이다. 두 다른 배경의 투과 변화와 투명도 감소 대체 스타일도 확인했다.
- 새 배경·확대 기능 적용 후 장면/저장 회귀 111개, 식사·영양·도감 회귀 13개, 모델 8개 통과. 그 뒤 마지막 픽셀 여백·작은 화면 CSS 조정은 위 집중 검사로 확인했으며 전체 회귀를 다시 실행했다고 보고하지 않는다.
- 원본/작은 내장형 UI 코드 일치, 1MiB 이하 공개 파일, JavaScript 구문·diff 검사 통과.

**남은 모바일 입력 문제:** 공개 확인용의 공개 샌드박스 프레임 검사에서 첫 `freshLeft` 터치 후 문이 닫힌 채 남는 기존 간헐 오류가 다시 발생했다. 후속 좌표·이벤트 진단 24개 문은 Locator 열기와 실제 화면 좌표 닫기에 성공했다. 원인은 미확정이며 최초 실패를 통과로 바꾸거나 이번 수정으로 해결됐다고 보고하지 않는다. 실제 iPhone/Safari·Notion·외부 HTML 렌더러 실행도 미확인이다. 수치와 결과는 [검사 기록](miniature-kitchen/approved-validation.json)을 따른다.

작은 내장형 약 930KB, 공개 확인용 약 953KB이며 모든 그림을 포함한다. 공개 프레임은 기존의 임시 세션·백업 방식을 사용한다. 휴대폰 전달 주소의 `Open the page` 안내는 [모바일 전달 문서](MOBILE_KITCHEN_PREVIEW.md)를 따른다.
