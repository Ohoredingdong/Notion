# 처음 첨부한 부엌 시안으로 구도 복구

사용자는9f 위젯에도 “점점더 이상해지고있다”고 정정했다. 이전 비교의 왼쪽에 썼던 Nov4 생성 보드는 사용자가 처음 첨부한 시안과 다른 구도였다. 이번 외형 기준은 [원래 재료 보드](../designs/kitchen-ux-storyboards/01-ingredients.png)이다. 이전 수치/기능/공개 통과는 외형 승인으로 취급하지 않는다.

## 실제 수정

- 창가·식물·나무 조리대와 열린 네 문 냉장고를 하나의 연속 사진으로 복구했다. 조각내 늘린 본체 벽/선반과 따로 붙인 회색 문을 제거했다. 새1254×1254 장면은 동일 비율로 투영하고 아래 바닥 여백만 원래 홈 구도에 맞춰 자른다.
- 작은 브랜드·실제 날짜·영양 요약을 위쪽에, 추가 버튼을 냉장고 안쪽 우하단에 놓았다. 요약 왼쪽10% 여백으로 창가를 드러낸다. 메뉴는 냉장고·레시피·기록·내 부엌을 유지한다. 사진/아이콘의 수치는 실제 기록을 쓰며 원본 보드의 예시 영양값을 채우지 않는다.
- 재료13종과 양념4종을 같은 광원·카메라의 투명 용기/자연 식재료 그림으로 교체했다. 기존 이름·수량·기한·사진과 v1 좌표는 보존하며, 실제 중앙벽에 맞춰 좌우 수납면을 따로 표시한다. 재료 종류별 그림 크기는 같은 칸의 x/y 이동으로 변하지 않는다.
- 열린 문 상태는 연속 사진을 사용한다. 닫힌 문에서는 해당 사진 영역과 문 선반 재료를 함께 숨기며 실제 프레임을 눌러 다시 연다. 기존 회전 전용 코드에 기대어 일반 모션에서 양념이 벽 위에 남던 회귀도 고쳤다.
- 44px 터치 영역이 작은 우유의 저장 좌표를 과도하게 제한하지 않도록 그림 폭으로 가로 경계를 계산한다. 실제 저장21개 자료320px에서 수평 이동 후 그림이0px 움직이던 문제를 고쳤다.
- 추가 버튼을 가리는 위치에는 재료 그림을 놓지 않도록 해당 선반의 사용 공간을 확보한다. 작은 화면에는44px 버튼을 위한12px 여유만 추가하며 사진은 늘리지 않는다. 우유 대표 그림은 중간 선반에도 설 수 있는 같은 비율의 크기로 맞춰 추가 저장한 다른 우유 로트와 겹치지 않는다.
- 짧은 홈 카드가 등록/검수 화면 높이를 줄이지 않도록 입력 대화상자는 별도 읽기 높이를 유지한다.320px 재료 상세만 네 입력 행과 두 저장/요리 버튼이 모두 보이는 높이로 확장하고, 닫으면 원래 홈 비율로 돌아간다. 음수 stickyfooter에 잘리던 버튼 하단도 복구했다.

상태/거래/OCR 모델과 B/C/D 흐름은 교체하지 않았다. 저장 키 `miniature-kitchen-preview-v1`과 version1, 재고·계획·식사·실제 지출·보상은 그대로다. 가짜 재고를 추가해 냉장고를 채우지 않는다. 기존 모든 원본 자산과 보드는 보존한다.

## 실행과 범위

[장면 품질](kitchen-original-scene-20261105/scene-quality.json)과 [음식 품질](kitchen-original-scene-20261105/food-quality.json)은 원본 해상도를 유지한4:4:4 AVIF가 같은 PNG의 WebP82 대비 cream/gray PSNR·SSIM 네 조건을 통과한 기록이다. 사진의 사용 픽셀 RGBA는 포장 전후 같고, 미사용 부분만0처리한다. 창작 편집과 전송 인코딩을 구분한다.

[실제 선택/원문·최종 재검사](kitchen-original-scene-20261105/native-qa.json), [이동/네 문](kitchen-original-scene-20261105/movement-and-doors.json), [상세 버튼](kitchen-original-scene-20261105/detail-actions.json)을 기록한다. 기본17개와 저장21개 자료의 실제 선택·원문 보존을 확인했으며, 발견한 수평 이동/일반 모션/버튼 잘림은 마지막 후보에서 각각 재검사했다.320/390/801에서 확인했다. 전체 기록을 바꾸거나 이름/수량으로 데모를 판정하지 않는다.

실제 사진의 개별 물체와 원본 보드의 모든 픽셀이 같다는 주장이 아니다. 기본 재료 수와 영양 미입력은 실제 자료에 따르며, 사용자의 최종 디자인 승인·실제 Safari/Notion 기기 검증·main 배포는 별도로 구분한다.
