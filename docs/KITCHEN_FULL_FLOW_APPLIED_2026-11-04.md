# 11월 4일 전체 동선 시안 실제 적용

사용자가 [새 전체 동선·상세 화면](../designs/kitchen-full-flow-20261104/DESIGN_SPEC.md)을 확인한 뒤 “제발 이렇게 수정해봐 너가 계획한 그대로”라고 요청했다. 이번 구현 기준은 Nov4의 5장과 24개 화면이다. 이전 Nov3 시안의 상단 영양 요약·떠 있는 추가 버튼을 최신 기준으로 취급하지 않는다.

## 적용한 화면과 저장 동작

| 흐름 | 실제 화면 구성과 연결 |
|---|---|
| 재료 A1–A6 | 작은 중앙 브랜드 → 냉장고 → 아래 영양 요약 → 넓은 추가 버튼 → 등록 방법 3개 → 제품/기한 사진 2장 → 원본과 4개 필드 검수 → 저장된 재료 강조 → 아래 상세 시트. 검수 전에는 재고가 바뀌지 않으며 상세 저장은 선택 로트의 수정한 필드만 바꾼다. |
| 레시피 B1–B6 | 추천 큰 사진과 작은 카드 2개·필터 → 사진/재료/실제 순서 상세 → 계획 또는 실제 식사. 계획은 날짜·끼니·분량만 저장한다. 실제 식사는 영양과 로트 차감을 함께 저장하며 취소는 해당 거래만 복구한다. |
| 기록 C1–C6 | 영양·영양제·전체 월간 달력·식비 탭 → 장보기 → 실제 구매 금액. 영수증당 지출 1건을 저장하고 같은 ID로 수정한다. 저장된 구매 품목만 A3→A4에서 개별 등록하며 중복 재고/지출을 막는다. |
| 성장 D1–D6 | 실제 첫 요리 목표 → 8종 도감 → 이미 지급된 첫 기록 보상 → 소품 4종 → 임시 배치 → 적용된 닫힌 부엌 → 냉장고 열기. 미리보기/취소는 꾸밈권을 쓰지 않으며 적용 때 소유권·배치·비용을 함께 저장한다. |

주 메뉴는 **냉장고·레시피·기록·내 부엌** 한 줄이다. 모든 화면이 같은 세로 프레임을 쓰고, 작은 화면의 주 버튼을 초기 화면에서 조작할 수 있게 압축했다. 긴 실제 조리 순서나 추가 원본 정보는 해당 상세 영역에서 펼친다. 사진은 원래 비율을 유지한다.

D5와 D6에는 같은 닫힌 냉장고 폭과 부엌 배경 기준을 사용해 적용 후 소품이 냉장고 앞면으로 겹치던 차이를 고쳤다. 보드의 모든 사진·배경 소품을 그대로 복제했다는 의미는 아니다. 기존 냉장고/음식 사진과 실제 저장 배치는 유지하며, 시안과의 화면 구성 비교와 기능 통과를 구분한다.

## 기록 호환성과 실패 복구

`miniature-kitchen-preview-v1` 및 envelope version 1을 유지한다. 기존 재고 ID·좌표·문 상태·계획·식사·지출·보상 이력과 알 수 없는 필드를 보존한다. 새 영수증 연결, 끼니/거래 표시 정보와 새 부엌 기본 소유권은 선택 필드다. 구버전의 무료 소품·배치에는 새 비용을 부과하지 않는다. 새 부엌만 기본 컵을 제공하며 첫 보상용 꽃을 미리 놓지 않는다.

트랜잭션은 저장 충돌을 먼저 검사한다. 영구 저장이 실패하면 재고·식사·워크플로를 함께 이전 상태로 되돌리고 현재 입력/미리보기를 남긴다. 실제 UI의 A4·B5·C6·D5 저장에 실패를 주입해 확인했다. 첫 요리 보상은 기록을 취소하고 다시 저장해도 재지급하지 않는다.

## 이미지와 전달 크기

데이지 화병·화이트 컵/트레이·우드 식물 액자·패브릭 바구니는 1254×1254 원본과 원래 비율의 크롭을 사용한다. 사용되는 949,038픽셀은 포장 전 PNG와 RGBA가 동일하다. 선택한 AVIF는 같은 원본의 WebP82 기준 품질 검사를 통과했다. 이전 꽃/컵의 중복 셀과 새 사진으로 대체한 기존 음식 셀의 미사용 영역만 전달 아틀라스에서 제외했다. 기존 중립 아이콘, 알 수 없는 재료/양념의 대체 그림, 예전 소품은 유지한다. 운영 공용 아트 소스는 바꾸지 않았다.

모든 그림·스크립트·스타일은 미리보기 안에 들어간다. 앱·위젯 및 모바일 래퍼 4개는 각각 1 MiB 제한 안이며 포장을 풀면 생성 원문과 바이트가 같다. 기존 이미지 해상도/인코딩 품질을 낮춰 한도를 맞추지 않았다.

## 실행 증거

최종 생성물과 실제 화면/검사 결과는 [증거 폴더](kitchen-fullflow-applied-20261104/)에 기록한다. 화면 검토의 수치는 명시적인 격리 예시 자료이며 실제 기본 기록으로 심지 않았다.

- 관련 Node 8개 스위트 100/100, 전송·포장 12/12, 문법 검사 16/16 통과.
- candidate3 실제 native UI의 A/B/C/D/구버전 보존 255개 단언을 320·390·801px에서 통과했다. 최종 CSS 후 전달 원문의 JS 동일성과 최종 화면을 별도 확인한다.
- 실제 Tesseract가 두 사진에서 우유·500mL·2026-11-30을 읽어 A4에 표시했다. 검수 저장 전 재고/저장 원문은 그대로였다. 결정적인 레이아웃 캡처의 제어된 OCR 응답과 실제 엔진 실행을 구분한다.
- 초기 OCR 실행은 Chromium의 환경 프록시 CA 신뢰 부족으로 엔진 로딩 전에 실패했다. 관리 환경의 해당 CA를 신뢰한 재실행에서 성공했다. 제품 소스나 모델 응답을 교체하지 않았다.

공개 휴대폰용 미리보기는 공유 출처의 저장을 격리하는 opaque iframe이므로 임시 세션이다. 원본 standalone HTML은 기존 v1 로컬 저장·백업/불러오기를 유지한다. 실제 기기 Safari/Notion 임베드 검증과 main/Pages 병합은 이번 Chromium 실행과 구분한다.
