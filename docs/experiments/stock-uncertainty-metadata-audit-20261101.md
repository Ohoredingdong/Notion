## Pre-registered defect hypothesis (before RED test)
The producer computes `directional_signal.uncertain` from the **already-frozen applied three-class probabilities** using the pre-existing, unchanged policy: `max(p) < 0.50 OR (top1 - top2) < 0.10`. The independent auditor checks selected applied probabilities and candidate provenance but, on code inspection, does not recompute this boolean. A synthetic change solely to the flag may therefore pass the current independent audit and make a genuinely uncertain call look certain. This is a *potential metadata integrity gap*, not evidence that actual ledger rows were altered.

**Narrowly bounded test**: Create a synthetic 30-minute valid forecast fixture (NO historical price) with both (a) correct uncertainty and (b) the same frozen probabilities but an inverted uncertainty flag. The auditor should accept (a) and fail closed on (b); test the opposite false-positive flag and malformed flag type too. Old forecasts with no directional-selection metadata remain valid. For modern directional-selection records, require that the signal is present; otherwise fail closed. The verification checks only the frozen boolean against the original policy and required display-safety booleans, without re-scoring, adjusting probability thresholds, changing recommendation permissions or accessing future prices.
