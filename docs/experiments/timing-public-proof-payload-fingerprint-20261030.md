## Hypothesis recorded before the code change

The public verifier `scripts/verify_stock_forecast_public.py` assigns `verification_id = digest(record)` before appending the published snapshot record. The independent auditor currently checks proof-ID collisions but does not independently recompute this known canonical content fingerprint. Consequently, a synthetic public row with fabricated earlier publication time and a new unrelated proof ID could be accepted as prospectively public and contribute to forward scores. Earlier PR #56 detects *conflicting reuse of the same proof ID*, not an individually inconsistent proof fingerprint. It is not evidence of actual tampering in production.

This hash is **only a payload-integrity consistency check**, not a GitHub-signed timestamp, independent public proof, human notification receipt, exchange data validation or defense against a deliberate rewrite that also recomputes its hash.
