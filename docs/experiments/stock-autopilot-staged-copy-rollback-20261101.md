**One testable engineering hypothesis:** `stock_forecast_autopilot.run` validates an isolated stage and checks the working snapshot, but copies the 11 resulting files one at a time into the working directory. A recoverable `shutil.copy2` failure after an earlier file was copied may leave a mismatched partial bundle while the failure report still claims `previous_evidence_preserved: true`. The existing synthetic test covers a failure **before** this publication loop, not an exception during the copy loop. This is a latent fault-path hypothesis; no actual corruption has been observed in the frozen evidence.

**RED control, specified before implementation:** run an entirely synthetic, dependency-free mocked pipeline that passes stage verification and supplies genuine-looking but strictly synthetic output files. Inject an `OSError` during a later destination copy, *after partially overwriting that destination*, and verify that the bytes of both an earlier successfully copied output and the failed destination are identical to their prior originals. On the original implementation this is expected to fail. An injected fault must never be recorded as a model improvement, learned sample, real price, or live-market outage.

**Bounded allowed repair:** if reproducible, add one small publication rollback guard with byte-for-byte restoration on a recoverable copy exception (including a partially written destination). Preserve the staged source, existing publication eligibility, strict-green-1.0, evidence schemas, complete frozen data, and unchanged model-selection criteria. Do not claim full filesystem/power-loss atomicity, human receipt, executable market data, profitable timing, or arbitrary self-healing. Failure and all trials must be logged. No real trades, credentials, user subscriptions, other automations, or shadow-candidate promotions.

**Required verification:** negative control RED; positive GREEN on the same regression; existing independent audit and relevant research unit/UI tests on an isolated branch; safe main merge only if these succeed. The branch must not publish synthetic data. Post-merge real audit and public deploy status are checked independently; no release benefit can be claimed from CI success. Trial budget: one fault hypothesis, one repair candidate, no model candidates, no retraining searches, zero performance-selection trials.
