## Reproducible engineering gap and prior work

PR #83 added a read-only `workflow_run: completed` audit trigger. The actual main forecast run [41157151233](https://github.com/Ohoredingdong/Notion/actions/runs/41157151233) completed at 2026-10-31 01:52:09 UTC; downstream audit [41157367970](https://github.com/Ohoredingdong/Notion/actions/runs/41157367970) started three seconds later. PR #83 explicitly left one provenance limitation open: downstream checkout of **latest main** is not evidence that the snapshot came from the **upstream run causing this event**. If another forecast run publishes before the dependent audit checks out main, a successful audit of the newer data could be mistaken for a verified handoff from the older trigger. The audit's arithmetic might still be valid on its own, but run-level lineage would not be established. This is a synthetic race condition, not an observed production data corruption or missing outcome. Prior provenance PRs #43/#47 concern learning-weight lineage, not upstream workflow-run binding.

## Hypothesis and fixed failure tests before the fix

A read-only, fail-closed, workflow-run-only check of the GitHub event's **actual upstream run ID and head SHA** against the archived main controller (`stock-forecast-autopilot.json.run_id/source_commit`) and latest public forecast snapshot (`stock-direction-forecast.json.source_run_id`), plus chronological consistency of the generated research/learning snapshots, will prevent a stale or unrelated main checkout from being represented as evidence from the invoking workflow. The upstream event carries a run ID and source head SHA that are independent of the files being checked. Do not use workflow success as market performance proof.

Synthetic tests must require rejection of (a) mismatched triggering run ID, (b) mismatched source commit SHA, (c) mismatched forecast source-run ID, (d) invalid/missing timestamp or inconsistent snapshot chronology, and acceptance of a matched valid fixture. Check the workflow statically for a conditional `workflow_run` step passing only the event-derived ID and SHA, retained schedule/manual invocation, read-only permissions, audit calculations, and controls. For a RED/negative test, wire the tests on a research PR before implementing the checker; preserve failure evidence. Count **one provenance engineering experiment**, **zero model/feature/threshold or candidate selection trials**.
