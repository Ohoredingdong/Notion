# 스마트홈 참고 이미지의 유리 질감·모듈 구성 · 2026-10-29

## 글자 정렬·반투명 재수정 · 현재 시안

사용자가 중앙 배치·투명한 느낌을 언급하며 앞선 시안의 저렴해 보이는 질감을 지적하고, 차분한 회색 스마트홈 화면을 추가로 제공했다. 이전의 불투명 크림색 모듈과 강한 흰 윤곽은 승인된 것으로 취급하지 않는다.

현재 화면은 `rgba(52,60,68,.78)`의 반투명 회색 바탕과 실제 `backdrop-filter`로 뒤쪽 냉장고 표면을 흐리게 비춘다. 카드의 흰 채움은 4.5%, 가장자리는 7%로 낮춰 두꺼운 흰 플라스틱 같은 윤곽을 줄였다. 글자에는 필터나 확대 변환을 적용하지 않는다. 투명 효과를 줄이는 OS 설정·미지원 브라우저용 불투명 대체 CSS도 있으며, 이 분기는 이번 브라우저 검사에서 별도로 실행하지 않았다.

두 제목·큰 숫자·메뉴명·재료명과 수량·미등록 재료를 각 영역의 중앙에 정렬했다. 헤더의 총 건수는 하단의 기존 `임박/경과/보관 n건`으로 표시해 제목 중심이 밀리지 않게 한다. 경과 문구와 색은 유지하며, 기록률 원은 차분한 민트색으로 표시한다. 변경 소스는 LCD CSS뿐이며 정보 계산·저장 형식·원본 그림·본체와 표시창 좌표/크기는 바꾸지 않는다.

기준은 `93b18969`다. 아래와 같은 예시·닫힌 문·고정 시각 조건의 전후 8쌍에서 본체와 표시창의 위치·크기가 같다. 집중 검사 12개 묶음(각각 11개 화면 조건·8종 메뉴), 원/막대의 0·40·100% 픽셀 검사 6개 구성과 모바일 크기·터치 6개 조건이 통과했다. 원본/작은 내장형 UI 코드도 일치한다. 이전 간헐 터치 문제를 해결했다고 주장하는 결과는 아니다.

뒤쪽을 두 가지 다른 색으로 바꿔 패널 안의 실제 픽셀이 `[98,103,108]`에서 `[87,94,102]`로 달라지는 것을 확인했다. 불투명 바탕을 유리처럼 칠한 효과와 구분하는 투과 검사다. 가장 밝은 흰 배경 위에 실제 RGBA 층을 합성한 보수적인 글자 대비는 기본/경과 상태와 3개 화면 구성에서 최소 약 4.65:1이다. [현재 검사 기록](miniature-kitchen/smoke-glass-validation.json)을 따른다. 실제 iPhone/Safari·Notion·외부 렌더러 실행과 최종 디자인 승인은 미확인이다.

작은 내장형은 앱 935,029바이트·위젯 935,032바이트, 공개 확인용은 958,401바이트·958,410바이트다. 전체 장면·식사 회귀는 이번에 재실행하지 않았다. 공개 프레임의 임시 저장과 PR API 차단 상태는 아래 기록을 따른다.

## 초기 모듈 시안 기록

아래 이미지와 확인 결과는 위 후속 피드백 전 화면을 보존한 기록이다.

사용자가 회색 유리 바탕, 크기가 다른 모듈과 녹색 원형 표시가 있는 스마트홈 화면을 새 참고 이미지로 제공했다. 이 방향은 앞선 평평한 iOS 표시창 제안을 대체한다. 기준은 `06e18988`이며 사용자 디자인 승인을 의미하지 않는다.

냉장고의 양쪽 표시창에 밝은 회색 그라데이션, 흰 가장자리, 부드러운 그림자로 유리 질감을 표현한다. 글자가 흐려지지 않도록 실제 텍스트에 필터나 확대 변환을 적용하지 않는다. 화면 바탕은 불투명하게 유지해 대비를 확보한다.

- 왼쪽 `유통기한 임박`: 오늘 수치를 큰 모듈로 두고 내일·2~3일 수치를 작은 두 모듈로 나눈다. 그 아래 넓은 모듈에 재료 그림·이름·수량·기한을 배치한다.
- 오른쪽 `오늘의 추천메뉴`: 음식 그림·메뉴명, 조리시간·난이도, 녹색 원형 재료 기록률·미등록 재료를 서로 다른 모듈로 배치한다. 기록이 바뀌면 기존 이름 일치 비율로 원형 표시를 갱신한다. 아주 짧은 화면은 기존 막대 표시를 사용한다.
- 원형 수치는 **레시피에 필요한 재료 이름의 기록 비율**이다. 재고 수량의 충분함·자동 영양 분석·실시간 냉장고 센서를 뜻하지 않는다. 이름을 전부 기록해도 `이름 기록됨`·`수량 확인 필요`라고 표시한다. 참고 이미지의 조명·온도·음악 스위치를 작동하는 냉장고 기능인 것처럼 추가하지 않는다.

변경 소스는 `scene.css`의 표시창 영역, `scene.js`의 비율 CSS 변수와 짧은 안내 문구다. 기존 이름 비교 계산·기한 처리·보관 모델·저장 키·원본 그림은 유지한다. 문을 누르면 열리고 다시 누르면 닫는 조작도 그대로다. 앱·위젯의 생성 파일을 함께 갱신했다.

## 확인 범위

같은 예시 데이터·닫힌 문·고정 시각 `2026-10-28T03:00:00Z`, Asia/Seoul과 동일한 크기에서 비교했다. 앱·위젯의 649×900·390×660·320×660·320×568 총 8쌍에서 본체와 표시창의 위치·크기가 같다.

집중 검사 12개 묶음은 각각 11개 화면 조건, 8종 요리명과 메뉴 영역, 수량·기한·빈 상태·경과 양념·재료 이름 기록률 및 직접 문 조작을 통과했다. 추가 6개 앱·위젯 구성에서 0·40·100% 상태의 실제 원/막대 녹색 픽셀 수와 표시값·접근성 값을 확인했다. 모든 이름이 기록됐을 때의 수량 확인 안내, 일반 화면의 재료 행 내부 배치와 미등록 메뉴의 재료 미입력 표시도 확인했다. 픽셀 분석의 초기 Pillow 의존성 부재는 설치된 ImageMagick으로 분석 방식을 바꿔 해결했으며 제품 코드는 바꾸지 않았다.

3개 화면 구성의 기본·경과 상태에서 실제 글자색과 회색 바탕의 보수적 하한 `#dad8d0`를 사용한 대비는 최소 약 4.74:1이다. 원본/작은 내장형 UI 코드 일치, JavaScript 구문과 `git diff --check`를 확인했다. 전체 장면·식사 회귀를 새로 실행한 것으로 보고하지 않는다.

**휴대폰 검사 이슈:** 기존 모바일 검사 첫 실행에서 `main.shell`이 `freshLeft` 문 터치를 가로챈다는 Locator.tap 시간 초과가 다시 발생했다. 추가 좌표·이벤트 진단은 6개 화면 조건의 24개 문 열기/닫기에 성공했고, 화면 좌표의 대상도 문과 일치했다. 원인은 여전히 미확정이며 처음 실패를 통과로 바꾸거나 이번 스타일 수정으로 해결했다고 보고하지 않는다. 실제 iPhone/Safari·Notion·외부 렌더러 실행은 미확인이다. [검사 기록](miniature-kitchen/glass-modules-validation.json)에 실패와 진단 통과를 구분한다.

작은 내장형은 앱 934,542바이트·위젯 934,545바이트, 공개 확인용은 957,878바이트·957,887바이트다. 공개 프레임의 임시 저장과 `Open the page` 안내는 [모바일 전달 문서](MOBILE_KITCHEN_PREVIEW.md)를 따른다. 검토 브랜치를 사용하며 기존 앱·main·Pages 배포는 바꾸지 않는다. 기존 PR API 403 차단 상태와 브랜치 비교 주소는 [앞선 검토 기록](IOS_KITCHEN_DISPLAYS_2026-10-29.md)에 있다.
