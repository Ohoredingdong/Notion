# 입체적인 미니어처 부엌 — 디자인·조작 시안

사용자는 생활형 재디자인을 거절한 뒤 **“보내준 사진처럼 입체적인 미니어처 부엌 — 냉장고·식재료·소품을 직접 만지고 꾸미는 느낌”**을 선택했다. 이번 작업은 선택한 방향을 앱·위젯에서 실제로 만져 볼 수 있게 만드는 **독립 시안**이다. 방향 선택을 완성 화면·게임 규칙·데이터 연결에 대한 승인으로 확대 해석하지 않는다.

브랜치: `design/miniature-kitchen-scene`. 기준: `5fe0eba5`. 기존 앱의 HTML·CSS·JavaScript·저장소는 수정하지 않는다. 거절된 시안을 삭제하거나 그 테스트 통과를 디자인 승인으로 해석하지 않는다.

### 채팅 미리보기의 이미지 깨짐 수정

사용자는 이미지·ZIP 대신 **이 대화 안에서 직접 조작하는 화면**을 요청했다. 일반 파일 링크가 소스 보기로 열렸으나, 이후 `sandbox:` 링크로 전달한 HTML은 사용자 스크린샷에서 UI가 렌더링되는 것을 확인했다. 따라서 “이 대화에서는 실행 화면 자체를 띄울 수 없다”는 앞선 설명은 정확하지 않았다. 제공된 도구로 사용자의 미리보기 UI를 직접 제어할 수 없는 것과, HTML 파일을 전달해 실행하는 것은 구분한다.

다만 외부 이미지 5개를 참조했던 약 54KB 경량판에서는 부엌 배경·냉장고·식재료가 누락되거나 흐린 덩어리로 표시됐다. 해당 이미지는 검증 환경의 HTTPS 요청에서는 원본과 같았지만, 그것이 사용자 미리보기의 표시를 보장하지 않았다. 사용자 브라우저의 실제 네트워크 기록은 없어 세부적인 차단·프록시 원인은 단정하지 않는다. 이전 경량판 검사도 검증한 이미지를 Playwright 요청 경로에 공급한 기능 점검이었으므로 실제 채팅 이미지 로딩의 성공 근거로 사용하지 않는다.

첫 내장형 수정본은 외부 이미지 참조를 제거하고 원본 그림 전부를 HTML 안에 포함했다. 외부 이미지용 `--asset-revision` 옵션도 제거했다. CSS·JavaScript·원본 그림·디자인·실제 앱 저장소는 바꾸지 않았다. 생성 위치는 `/workspace/artifacts/kitchen-embedded-preview/`이며, 앱/위젯은 각각 9,345,516/9,345,519바이트였다. 하지만 2026-10-24 사용자가 이 수정본도 “안 나온다”고 답했다. 빈 화면·소스 보기·파일 열기 오류 중 어떤 상태인지는 미확인이며, 아래 내부 테스트 통과를 사용자 화면 성공으로 해석하지 않는다.

[수정본 브라우저 결과](miniature-kitchen/embedded-delivery-results.json)는 30개 통과·실패 0이다. 기존 조작 29개에, 외부 이미지 요청을 모두 차단한 상태에서 원본 그림 5개의 실제 디코딩과 해상도를 확인하는 회귀 검사를 추가했다. 방·냉장고는 1536×1024, 소품은 1286×1223, 식재료는 1254×1254, 양념은 1448×1086이다. 이 검사는 이미지 응답을 모의로 공급하지 않으며 문서 외 네트워크 요청은 0이다. 기존 기록 키 접근도 0회다. 실제 사용자 클라이언트·Notion·Safari 확인은 별도로 남아 있다.

같은 640px 폭·예시 데이터·시각에서 [외부 이미지 차단 재현](miniature-kitchen/asset-blocked-before-640.png)과 [이미지 내장 후](miniature-kitchen/asset-embedded-after-640.png)를 비교했다. 전자는 사용자 스크린샷을 복제한 것이 아니라 의존성 실패를 로컬에서 재현한 화면이다. 런타임 결과는 `/workspace/.notion-cloud/miniature-scene/embedded-delivery-verified/`에 보관한다.

### 작은 내장형 수정본 — 사용자 표시 확인 미완료

외부 이미지 의존성과 큰 파일을 함께 줄이기 위해 `--compact`를 추가했다. 원본 이미지는 보존하고, 빌드 중 ImageMagick으로 WebP 품질 82·알파 품질 100을 인코딩한다. 그림 해상도·스프라이트 좌표는 유지하고, 현재 시안에서 사용하지 않는 식재료·양념 아틀라스 칸만 제외한다. 실제 앱의 전체 그림 라이브러리는 수정하지 않는다. 현재 재료 선택 8종, 요리 2종, 양념 4종, 소품 4종과 기본 대체 그림은 포함한다. 선택 목록을 늘릴 때는 `COMPACT_SPRITES`와 실제 표시 검증도 함께 갱신해야 한다.

```bash
python scripts/build_miniature_kitchen_preview.py --compact \
  --output-dir /workspace/artifacts/kitchen-compact-preview
```

앱 936,128바이트, 위젯 936,131바이트, 비교판 1,896,638바이트다. 개별 앱/위젯에 1MiB의 자체 전달 예산을 두고 초과하면 파일을 쓰지 않는다. 이 값은 확인된 채팅 플랫폼 제한이 아니다. 기본 빌드의 세 결과는 이전 원본 내장형 파일과 바이트 단위로 같고, CSS·동작 코드·저장 키·원본 이미지도 바꾸지 않았다. 이전 전달 경로 두 곳의 파일 역시 작은 내장형으로 교체했다.

[작은 수정본 검사 결과](miniature-kitchen/compact-delivery-results.json)는 33개 통과·실패 0이다. 외부 이미지 요청은 모두 차단하며 응답을 모의로 공급하지 않는다. 5개 이미지의 해상도·디코딩 외에, 실제 재료/요리/꾸미기 선택 화면을 열고 각 SVG가 참조하는 영역에 보이는 그림 픽셀이 있는지 확인해 빈 아틀라스 칸을 잡는다. [앱 렌더링](miniature-kitchen/compact-app-1120.png)을 직접 확인했고, 같은 1120×1000px의 원본 내장형 화면과 SSIM은 0.987499였다. 손실 압축 결과이므로 픽셀이 동일하다고 보고하지 않는다. [전달 크기와 범위](miniature-kitchen/compact-delivery-manifest.json)도 기록했다.

2026-10-25 사용자가 보낸 스크린샷에서는 UI와 배경·식재료가 실제로 표시되는 것을 확인했다. 이어 사용자는 냉장고 위치와 작아진 크기를 지적했다. 이는 디자인 최종 승인이나 실제 기능 연결 승인이 아니다. 초기 작은 파일의 런타임 검증은 `/workspace/.notion-cloud/miniature-scene/compact-delivery/`에 있다.

### 2026-10-25 냉장고 크기·바닥 배치 수정

600px 높이 안에서 냉장고를 높이의 약 79%로 제한하고 문 버튼 공간을 아래에 예약해, 위젯 폭이 넓어져도 본체가 약 271px에 머물고 바닥 위에 떠 보였다. 앱의 작은 화면에도 비슷한 높이 제한이 있었다. 버튼을 `.room` 바깥의 `.kitchen-view`로 분리하고, 작은 화면의 냉장고 폭을 공간의 78%·최대 440px로 정한다. 320px에서는 82%로 기존 크기를 유지한다. 높이는 본체 비율에 맞춰 늘리고, 아래 여백은 18px로 둔다. 560px 이상에서는 빈 설치 공간의 왼쪽에, 그보다 좁은 화면에서는 양쪽 열린 문이 보이도록 중앙에 배치한다. 재료도 본체 크기에 따라 48~80px로 커진다.

[위치·크기 수치](miniature-kitchen/fridge-layout-comparison.json)에서 위젯의 본체 왼쪽은 약 177px에서 60px로, 본체 배치 상자와 장면 하단 간격은 약 109px에서 19px로 바뀐다. 1120px 앱의 냉장고 위치·본체 크기는 유지한다. 실제 이미지 원본과 색감·재료·저장 키는 바꾸지 않았다.

큰 냉장고의 짧은 화면 점검에서 손가락을 잡은 채 아래 냉동실로 끌 때 화면이 따라 내려가지 않는 실패를 확인했다. 가장자리에서 자동 스크롤하고 놓기·취소·화면 전환 때 멈추도록 수정했다. [최종 브라우저 검사](miniature-kitchen/fridge-layout-browser-results.json)는 52개 통과·실패 0이다. 앱/위젯 649px, 649×660 짧은 위젯, 기존 1120/640/390/320px와 네 문 노출·바닥 간격·그림 아래 버튼·양념 편집·소품·외부 요청 및 저장소 접근 0을 확인했다. [1120→649→390→320→1120 크기 변경](miniature-kitchen/fridge-layout-resize-results.json)에서도 수정한 수량과 열린 문, 모든 예시 상태가 유지됐다.

새 전달 경로는 `/workspace/artifacts/kitchen-size-fixed/`다. 앱/위젯은 각각 937,565/937,568바이트이며 이전 세 전달 경로도 갱신했다. 기본 원본 내장형 세 HTML도 원본 템플릿과 함께 재생성했다. 런타임 증거는 `/workspace/.notion-cloud/miniature-scene/fridge-layout/`에 있다. 실제 사용자 화면에서 새 크기와 배치에 대한 최종 디자인 승인을 받은 것은 아니다.

화면은 예시 재료를 메모리에만 갖고 시작한다. 기존 재료·기한·위치·생활 기록을 **읽거나 저장하지 않는다**. 새로고침하면 원래 예시로 돌아간다. 앱과 위젯 시안끼리도 수정 내용을 공유하지 않는다. 화면에 시안·예시·초기화를 표시한다. 이는 기존 앱 데이터를 초기화한다는 뜻이 아니다.

## 선택한 방향의 표현

크림색 타일, 아침 햇빛, 나무 조리대, 흰색 에나멜 냉장고, 유리 양념병, 도자기 식기와 식재료를 한 공간에 배치한다. 냉장고와 소품은 배경에서 분리된 요소로 움직인다. PNG 소재와 SVG 뷰포트·CSS 입체 회전을 조합한 화면이며, 실시간 WebGL 3D 모델을 새로 제작한 작업은 아니다.

- 흰색 4도어: 위 왼쪽/오른쪽 모두 냉장, 아래 왼쪽/오른쪽 모두 냉동. 네 문을 각각 열고 닫는다.
- 위 두 문 디스플레이: 예시 기한 임박 재료와 요리 카드를 표시한다. 기본은 위 왼쪽 문을 열어 식재료가 보이게 시작한다.
- 문을 열어야 해당 칸의 재료를 선택하고 옮길 수 있다. 재료·양념은 누르면 수량/기한/위치를 바꿀 수 있고, 드래그·방향키로 배치한다.
- ‘꾸미기’에서 도자기 도구통·데이지 유리병·우드 트레이와 찻잔·쿠키 유리병을 고른다. 조리대에서 겹쳐 놓기·앞/뒤 순서·치우기를 확인한다.
- 뒤로 가려진 소품은 ‘놓아둔 소품 보기’ 목록에서 선택해 다시 앞으로 가져올 수 있다.
- 재료 담기와 요리 카드 두 가지 선택도 시안 안에서 조작한다. 실제 레시피 추천·재고 차감·식단 기록을 구현했다고 보고하지 않는다.
- 앱은 부엌 전체를 보여준다. 작은 앱/위젯은 냉장고·양념 선반·조리대를 골라 같은 소재를 크게 본다. 한 장의 앱 화면 전체를 축소해 넣지 않는다. 재료 조작은 최소 44px, 주요 문 디스플레이 글씨는 12px다.
- 허브·잎 보상·레벨·강제 캐릭터를 넣지 않는다. 성장·보상·목표 요구는 남아 있으며 **구체적 방식은 미정**이다.

## 구현하지 않은 범위

사진 2장/전체 냉장고 자동 인식·아이콘 생성, 실제 식비·영양·영양제·월간 기록 연결, 기존 8개 레시피 추천 로직 연결, 실제 재고 차감·취소·동기화·배치 저장은 이번 시안 범위에 포함하지 않는다. 숫자·기한·요리 선택은 화면 조작용 예시다. 기존 앱에 있던 기능이 이 시안으로 대체되거나 완료됐다고 말하지 않는다. 커뮤니티·유료화는 계속 보류다.

생성 원본은 `/workspace/generated_images/`에도 유지한다. 파일을 잘라 덮어쓰지 않고 SVG 클립으로 각 부분을 표시한다. 생성 배경/냉장고/소품의 원본은 각각 `exec-919a5bbc-1ed8-4863-a627-c2127df409da.png`, `exec-264102cf-3dc5-4698-8a5d-dd4d421e245f.png`, `exec-8ef38d16-a1a2-4be6-bfd3-9012a8a3ff21.png`다. 선택 방향의 비교 그림은 `exec-d05e7adf-c583-45be-a7d7-417a6be7ece4.png`이며, 기존 코드의 실행 스크린샷이 아니다.

## 검증과 다음 작업

```bash
source /workspace/.notion-cloud/activate.sh
python scripts/build_miniature_kitchen_preview.py
python scripts/test_miniature_kitchen_browser.py --output /tmp/miniature-kitchen-browser
```

검증은 실제 Chromium과 예시 자료로 수행한다. 앱/위젯별 반응형 배치, 네 문·닫힌 칸 차단, 마우스/터치 이동, 수량/기한·양념 편집, 소품 선택/배치/순서, 메모리 초기화, 외부 자산 요청과 기존 저장소 접근 0, 비교용 sandbox iframe을 점검한다. 테스트 결과·화면 증거는 확정 후 아래에 기록한다. 실제 Notion·실기기 Safari·사진 인식·기존 앱 연동의 검증을 대신하지 않는다.

시각·조작 검토 후 같은 소재/배치를 기존 `UMFStore`·냉장고 상태·레시피·양념 기능에 연결하는 것이 다음 단계다. 저장 키를 대체하지 않고 같은 자료·폭의 전후 화면과 기존 회귀를 확인해야 한다. 보상은 꾸미기 선택권·목표의 구체적 정책부터 정하고, 허브·잎을 승인 없이 되살리지 않는다.

## 실행 증거

[브라우저 29개 사례 통과, 실패 0](miniature-kitchen/browser-results.json). 앱 1120/390px·위젯 640/390px에서 전체 조작 흐름, 양쪽 320px에서 배치·가로 넘침·문 개폐·닫힌 칸 입력 차단을 확인했다. 비교판의 두 opaque sandbox iframe과 포함된 시안 크게 열기도 확인했다. 개별 시안·비교판 모두 문서 외 자산 요청 0이다.

검증 중 기존 저장 키 4개의 정확한 원문을 심어 두고 `getItem`·`setItem`·`removeItem`·`clear` 호출을 기록했다. 시안의 읽기/쓰기 호출은 **0회**였고, 전체 조작 전후 원문이 같았다. 새로고침 후 시안 예시만 원래대로 돌아가는 것도 검사했다. 이 검증은 실제 개인 데이터에 접근한 것이 아니다.
