# 한끼의 부엌 — 화면·동작 설계 인수인계

기준일: 2026-11-02 Asia/Seoul. **설계 시안이며 기존 앱·위젯에 적용한 구현 결과가 아니다.**
최종 이미지는 **00 전체지도 / 01 등록 / 02 식단기록 / 03 생활기록 / 04 성장꾸미기**이며, 아래 A~D 화면 ID는 이 다섯 설계 보드의 동작 기준이다.
화이트 4도어 냉장고·따뜻한 미니어처 부엌을 유지하며 캐릭터 육성·커뮤니티·결제·확률형 보상은 범위에 넣지 않는다.

## 1. 공통 화면 규칙

- 하단 한곳의 메인 메뉴는 **냉장고 / 식단 / 기록 / 내 부엌** 네 개다. 별도 양념 선반·조리대 공간 탭은 두지 않는다.
- 기본 터치 영역은 최소44px, 입력 글씨는16px 이상으로 한다.
- 메인 메뉴는 허브 화면에 표시한다. 촬영·검수·상세·확정·배치 편집 단계는 뒤로/닫기로 맥락을 유지한다.
- 한 화면에는 강조된 주 행동 하나를 둔다. 보조 행동은 외곽선/텍스트 버튼으로 구분한다.
- 상단 브랜드, 탄단지 요약, 냉장고, 현재 필요한 행동 순으로 위계를 만든다. 영양 요약을 모든 입력/편집 화면에 반복하지 않는다.
- 재료 상세는 냉장고 또는 목록 위의 하단 시트로 연다. 요리·사진·기록 입력은 집중 화면으로 연다.
- 뒤로/닫기는 **진입한 화면**으로 돌아간다. 목록의 종류·보관 위치·검색·정렬·스크롤, 계획의 날짜·끼니, 입력 중 초안을 보존한다. 등록을 뒤로 가도 선택 사진과 수동 수정값을 유지하며, `등록 취소`를 명시적으로 누른 경우에만 확인 후 초안을 폐기한다.
- 닫은 뒤 초점도 진입 버튼/재료로 돌려준다. 저장 중에는 중복 탭을 차단하고 동일 요청을 한 번만 반영한다(idempotent). 저장 후 결과와 변경한 항목을 표시한다.
- 전체 페이지를 길게 쌓지 않는다. 긴 목록/상세 내용만 해당 영역에서 스크롤하며 작은 글씨로 모든 내용을 억지로 넣지 않는다.

## 2. 00 전체 동선 — 같은 홈에서 시작하는 다섯 연결

| 홈에서 누르는 곳 | 도착 화면 | 다음 연결 |
| --- | --- | --- |
| 헤더 `재료 목록` | 전체 재료 목록 | 행 선택 → A6 재료 상세 |
| `재료 추가` | A2 등록 방법 | A3 사진 또는 A4 직접 입력 |
| 하단 `식단` | B1 오늘의 요리 | B2 요리 상세 |
| 하단 `기록` | C1 오늘의 기록 | 영양제·월간·식비 보기 |
| 하단 `내 부엌` | D1 나의 목표 | 도감·보상·꾸미기 |

목록은 **전체 / 식재료 / 양념** 종류 필터와 `보관 위치 전체⌄`를 제공한다.
냉장·냉동·문 안쪽·냉장고 밖에 있던 재료를 모두 포함한다. 같은 이름의 재료도 수량·기한이 다른 묶음을 보존한다.
양념은 이 목록과 냉장고 문에서 같은 상세로 관리한다. 목록을 열 때 데이터를 이동하거나 재분류하지 않는다.

## 3. A — 재료 등록과 관리

| 화면 | 보여주는 정보·주 행동 | 결과와 돌아갈 곳 |
| --- | --- | --- |
| A1 냉장고 홈 | 탄단지 현재량(내 목표), 큰 냉장고, 기한 요약, 재료 목록·추가 | 재료 터치 → A6 / 추가 → A2 |
| A2 등록 방법 | 제품·기한 사진 2장 또는 직접 입력 | 사진 → A3 / 직접 입력 → A4의 입력형 화면 |
| A3 사진 2장 | 제품 사진과 기한 사진을 각각 선택·교체. 두 원본이 준비되면 `사진 읽기` | 읽는 동안 진행/취소 표시 → A4 |
| A4 검수·저장 | 원본 사진과 후보 이름·수량·기한·개봉일·보관 위치, 아이콘/제품 사진 표현 선택 | 틀린 값 수정 후 `확인하고 담기` 한 번 → A5 |
| A5 저장 후 홈 | 추가한 재료만 잠깐 강조, 저장 완료 표시 | 재료 터치 → A6 / 다른 작업 → 각 허브 |
| A6 재료 상세 | 전체 이름, 묶음 수량·단위, 기한·개봉일·보관 위치, 수정/사용 내역 | 수정 저장 → 진입한 냉장고/목록 / `이 재료로 요리` → B1 필터 |

- A4에서 인식 후보 검수와 필수 수정·최종 저장을 합치는 것은 **새 UX 제안**이다. 사진을 고르거나 읽기만 해서는 저장하지 않는다.
- 읽기 실패/낮은 확신/날짜 모호함은 해당 필드에 확인 필요를 표시한다. 원본과 입력을 유지한 채 직접 입력하거나 재촬영할 수 있다.
- 이름 외 모르는 수량/기한은 `미입력`으로 구분한다. 임의 날짜·수량·보관 온도를 만들어 채우지 않는다.
- 기본 저장은 새 묶음이다. 합치기는 같은 기한·개봉일·호환 단위를 확인한 뒤 사용자가 명시적으로 선택한 경우만 수행한다.
- A6 닫기: 냉장고에서 열었으면 냉장고로, 목록에서 열었으면 같은 목록 상태로 돌아간다.

## 4. B — 요리 선택에서 계획 또는 먹은 기록으로

| 화면 | 주 행동 | 저장 시점·도착 화면 |
| --- | --- | --- |
| B1 추천 요리 | 보유/부족 재료, 입력한 영양·원가 기준의 요리 카드 선택 | B2. 미입력 조건을 알려주며 가짜 정확도를 표시하지 않음 |
| B2 요리 상세 | 준비 재료·부족 재료·조리 순서·1회분 영양/예상 재료비 | `식단에 넣기` → B3 / `먹었어요` → B4 |
| B3 식단 계획 | 날짜·아침/점심/저녁·계획 분량 확인 후 `계획에 추가` | 계획만 저장 → B5. 재고·섭취량·실지출은 변경하지 않음 |
| B4 먹은 양 확인 | 실제 날짜·분량, 반영 영양값, 사용할 재료 묶음과 수량의 전→후 확인 | `식사 기록하기` 확정 때 식사·영양·실제 재고 차감 내역을 단일 거래로 반영 → B6 |
| B5 계획된 식단 | 날짜/끼니별 계획, 분량, 부족 재료, 기록 여부 | `먹었어요` → 같은 계획·분량을 채운 B4 / 계획 수정·삭제 |
| B6 기록 완료 | 방금 기록한 식사, 갱신된 하루 균형, 차감 내역, 실행 취소 | `기록 보기` → **C1**, 냉장고로 → A5. D 보상 화면을 기록의 기본 도착지로 쓰지 않음 |

- 계획/분량 화면을 열거나 닫기만 해서는 재고와 영양을 바꾸지 않는다. 완료한 계획은 중복 기록 대신 기록 보기로 연결한다.
- 수량·단위가 불확실한 재료는 수량 검수 또는 차감 제외를 명확히 선택한다. 팩/개를 임의 g으로 변환하지 않는다.
- 취소는 확정한 단일 거래를 기준으로 실제 차감한 원래 묶음/수량과 해당 식사·영양을 연동해 역반영한다. 나중에 수정한 다른 기록 전체를 덮어쓰지 않는다.
- 실행 취소는 완료 알림뿐 아니라 C1의 기록 상세에도 남긴다. 취소한 계획은 다시 미기록 상태로 표시한다.

## 5. C — 영양·영양제·월간 기록과 실제 식비

| 화면 | 내용·행동 | 연결/저장 |
| --- | --- | --- |
| C1 오늘의 기록 | 끼니별 식사·하루 합계·내 목표, 기록 수정/취소 | 영양제 → C2 / 월간 → C3 / 식비 → C4 |
| C2 영양제 | 직접 등록한 제품·내 복용 일정·오늘 체크 | 체크/취소를 해당 날짜에 저장. 식사 영양값에 합산하지 않음 |
| C3 월간 | 기록일·끼니·식사 영양 비율·입력한 실제 지출 | 날짜/월 선택 → 해당 기록. 누락이 있으면 계산 범위를 함께 표시 |
| C4 식비 예산 | 월 예산·실지출·남은 금액·지출 내역 | `장보기` → C5 / 예산·지출 수정 |
| C5 장보기 | 부족 재료와 직접 추가한 구매 항목·예상 금액 | 구매한 항목 선택 → C6 |
| C6 구매 확인 | 실제 수량·가격·구매일·합계 검수 | `구매 기록하기` 한 번 → C4 갱신. 선택적으로 재료 등록 → A4 |

- 구매 확인은 실제 지출을 반영한다. 요리의 예상 원가나 재고 소비를 실제 구매 지출에 다시 더하지 않는다.
- C6 이후 재료 등록을 건너뛰거나 취소해도 확정한 구매 기록은 유지한다. A4 저장으로 지출을 중복 추가하지 않는다.
- 구매 수정/취소는 원래 지출 거래를 수정/역반영한다. 반복 누름/재진입으로 같은 구매가 두 번 등록되지 않게 한다.

## 6. D — 목표·도감·한 번의 보상과 꾸미기

| 화면 | 내용·주 행동 | 다음/취소 |
| --- | --- | --- |
| D1 나의 목표 | 영양 기록·새 요리 기록 등 선택한 목표와 실제 진행 | 도감 → D2 / 꾸미기 소품 → D4 |
| D2 요리 도감 | 모든 요리 기본 정보 열람, 미기록/기록 스탬프 구분 | 요리 → B2 / 첫 실제 기록의 보상 확인 → D3 |
| D3 첫 기록 보상 | 처음 기록한 요리와 지급된 꾸밈 보상 확인 | `소품 고르기` → D4. 열람만으로 보상 지급하지 않음 |
| D4 소품 선택 | 보유/미보유, 필요한 꾸밈권, 선택 결과를 명확히 표시 | 필요한 교환을 확정해 보유한 뒤 `배치하기` → D5 |
| D5 배치 미리보기 | 소품 위치·앞뒤 순서·외형 미리보기, `적용`과 보조 `취소` | 적용 → D6 / 취소 → 편집 전 배치 복원 |
| D6 적용한 홈 | 적용된 외형·소품과 완료 표시 | 계속 사용 → A1 / 다시 꾸미기 → D5 |

- D5의 적용 전 미리보기/취소 복원은 **새 설계 동작**이다. 편집 중 이동을 즉시 확정 저장하는 것과 구분한다.
- D4에서 이미 획득한 소품의 보유권은 D5 취소로 삭제하지 않는다. 취소가 새 보상이나 꾸밈권 중복 지급의 계기가 되지 않는다.
- 첫 기록 보상은 요리별 한 번이다. 식사 취소 후 같은 요리를 다시 기록해도 보상을 반복 지급하지 않는다.
- 미기록 요리의 재료·순서 같은 기본 정보를 잠그지 않는다. 열람 상태, 실제 요리 기록, 보상 수령 상태를 구분한다.
- 꾸미기 적용/취소로 식재료 수량·기한·보관 위치를 바꾸지 않는다.

## 7. 모든 보드에 공통인 입력 예시

- 날짜: **2026년11월2일 월요일**. 계란 기한11월5일, 우유11월10일, 밥11월20일. 계란은 오늘 기준3일 이내이며 ‘오늘까지’로 쓰지 않는다.
- 내 하루 목표: 탄수화물230g / 단백질70g / 지방60g. 개인이 설정한 예시 목표이며 공식 권장량으로 표현하지 않는다.
- 아침 기록: 탄100g·단35g·지20g = **720kcal**.
- 점심 볶음밥1회분 입력: 탄60g·단20g·지15g = **455kcal**.
- 점심 기록 후 하루: 탄160/230g·단55/70g·지35/60g = **1,175kcal**. 455kcal를 하루 합계로 표시하지 않는다.
- 월간 예시도 같은 두 기록뿐이다: **기록1일·2끼**, 합계160/55/35g, 탄단지 에너지 비율 **54.5% / 18.7% / 26.8%**(4·4·9kcal/g).
- 11월 식비: 예산300,000원 / 실지출128,000원 / 남은172,000원.
- 실제 구매18,300원 확정 후: 실지출146,300원 / 남은153,700원. 식사 기록과 꾸밈권은 이 계산을 바꾸지 않는다.
- 영양·가격은 시안용 입력 예시다. 값이 없으면 `미입력`, 목표가 없으면 `목표 설정`을 표시하고 0/추천량으로 대신하지 않는다.

## 8. 구현과 분리할 사항

현재 작업은 화면·동작 제안이며 **기존 앱·위젯·저장 키·데이터를 수정하지 않았다.**
제품/기한 사진의 글자 OCR·수동 검수와, 전체 냉장고의 객체 자동 판별을 구분한다.
전체 사진 재료 자동 판별·새 미니어처 생성·공식 성분/가격DB·개인 권장량/건강 조언·기기 간 동기화는 연결 완료처럼 표시하지 않는다.
A4 한 화면 검수/저장과 D5 미리보기/적용/취소를 실제 구현할 때는 초안 보존·중복 저장 방지·원본 보관·실패/취소·접근성·작은 화면을 별도 검증한다.
