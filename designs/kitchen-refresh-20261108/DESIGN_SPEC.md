# 한끼의 부엌 — 디자인 재설계 시안

상태: **검토용 디자인 제안. 제품 구현·사용자 최종 승인·운영 배포와 구분한다.**

2026-11-08 사용자의 “디자인부터 다시해봐” 요청에 따른 작업이다. 기준 구현은 `84c5fe570d2eea713fc9931b99ca1dc6abdf7bf3`다. 이 제안은 기존 제품 규칙이나 확정 시안을 자동으로 대체하지 않는다. 사진·영양제·식사·지출·소품·저장 형식·금융 자동화는 수정하지 않는다.

## 시각 방향

- 기존의 따뜻한 부엌을 유지하고, 부엌·냉장고·식재료·병·소품을 같은 부드러운 사실적 일러스트 질감으로 통일한다. 강한 창문 그림자·금속 반사·잘라 붙인 음식·두꺼운 갈색 그림자는 줄인다.
- 720×764 기준의 거의 정사각형 위젯이다. 휴대폰 외곽·상태바를 넣거나 작은 임베드를 긴 세로 앱으로 늘리지 않는다. 구현 시에는 현재 호스트 크기와 고정 읽기 크기의 조작을 다시 검증한다.
- 상단의 브랜드·영양 요약·영양제를 하나의 낮고 일관된 영역으로 정리한다. 영양제는 냉장고 바로 위에 유지한다. 등록 전에는 큰 빈 판과 `0/0` 대신 한 줄 등록 안내를 표시한다.
- 정보 순서는 제목 → 주요 값/제품 → 보조 설명 → 행동이다. 카드 외곽·제품 열·배경 설치 공간의 중심과 여백을 함께 맞춘다.
- 기본색은 아이보리·따뜻한 회색·연한 오크·절제된 세이지다. 코랄은 주 행동과 선택 상태에 집중한다. 식재료는 같은 시점·빛 방향·크기·선반 접지 그림자를 사용한다.

건강상식과 식비를 새 그림에서 감추지 않는다. `레시피`는 메인 메뉴 명칭이고 계획을 보관하는 `내 식단`은 하위 기능이다. 실제 기능을 구현하거나 검증한 화면으로 생성 시안을 보고하지 않는다.

## 표시 상태

- 제품 없음: 영양제 등록 안내 한 줄. 큰 빈 선반을 그리지 않는다.
- 제품 있음: 이름·오늘 체크 상태·관리 동작을 같은 낮은 행에 정렬한다. 긴 이름과 여러 제품은 실제 작은 화면에서 추가 검증한다.
- 영양 미입력: 미입력을 분명히 표시하고 가짜 기본 영양값이나 목표를 추가하지 않는다.
- 이미지에 있는 수치·제품·식사·금액은 **시안용 예시**이며 사용자 기록이나 제품 초기 데이터로 사용하지 않는다.

## 구현 전에 확인할 기준

이 단계의 결과물은 새 홈 이미지와 같은 크기의 네 탭 디자인 보드다. 이미지의 좌표·한글·데이터는 실행 가능한 UI와 동일하다고 가정하지 않는다. 실제 구현 단계에서는 원본 자산을 분리하고 같은 데이터/뷰포트의 전후 화면, 등록 전/후, 작은 임베드, 문 열림/닫힘, 키보드/터치, 기존 자료·거래를 다시 검사한다. 디자인 이미지 생성 성공을 브라우저 테스트 통과로 세지 않는다.

## 구현에 넘길 자산·표시 상태 기준

- 열린 냉장고·닫힌 냉장고·꾸미기 방은 같은 본체 모델과 종횡비를 사용한다. 배경마다 다른 냉장고 사진을 늘려 붙이지 않는다. 본체 하나와 네 문, 같은 바닥 접점을 기준으로 상태를 바꾼다.
- 달력의 음식 그림은 실제 식사 기록이 있는 날에만 둔다. 미래 계획은 실제 식사 기록과 다른 표시를 사용하며, 보기 좋게 만들려고 미래의 실제 식사 기록을 추가하지 않는다.
- 레시피8개는 처음부터 비교할 수 있는 구성을 유지한다. 작은 폭의 읽기 크기·카드 높이는 이미지를 통째로 줄여 해결하지 않고320/390px 배치로 별도 검증한다.
- 이 이미지는 생성된 평면 시안이다. 같은 좌표의3D 모델·정확한 글자 크기·44px 조작 영역을 보장하지 않는다. 구현 전에 공통 소재와 치수를 확정한다.
