# 한끼의 부엌 · 전체 동선과 상세 화면 재설계

2026-11-04 Asia/Seoul. 사용자가 요청한 전체 동선1장과 네 가지 상세 보드, 총24개 주요 화면이다. 각 화살표는 누르는 버튼과 다음 화면 ID/이름을 연결한다. 따뜻한 흰색4도어·창가 부엌과 하단 냉장고/레시피/기록/내 부엌 메뉴를 유지한다.

- [00 전체 동선](00-overview.png)
- [01 재료](01-ingredients.png): 사진2장 → 인식값 검수 → 확인 저장 → 재료 상세. 재촬영·직접 입력·수정 저장·추천 요리 진입 포함.
- [02 식단](02-meals.png): 요리 상세에서 계획 작성과 실제 먹은 양으로 분기. 실제 식사 저장에서만 영양·재고를 함께 반영하고 거래별 취소로 복구.
- [03 기록](03-records.png): 영양·영양제 상세·전체 월간 달력 → 월 식비 → 장보기 → 실제 결제 지출 저장. 구매 재료는 별도 검수·등록.
- [04 성장](04-growth.png): 첫 요리 기록 → 도감·보상 → 소품 선택 → 배치 미리보기 → 취소 또는 적용.

[동작 명세](DESIGN_SPEC.md)와 [화면·버튼 데이터](flows.json)에24개 화면과99개 전이, 저장 전후 상태를 기록한다. 계획과 실제 식사, 예상 금액과 결제 지출, 배치 미리보기와 적용 확정을 구분했다. A6 수정 저장은 그림의 화살표와 동일하게 A5로 돌아간다.

새 설계 시안이며 이미지의 수치·재료·영양·지출·보상은 일관된 설명용 예시다. 실제 사용자 기록을 변경하거나 현재 앱이 이 동작을 구현했다고 주장하지 않는다. 특히 적용 시 소품 획득·꾸밈권 차감·배치를 함께 확정하는 방식은 새 제안이다. 앱/위젯 소스·운영 HTML·기존 미리보기·저장 키·main/Pages는 변경하지 않았다.

모든 이미지는 image_gen으로 생성하고 선택한 원본 PNG 바이트를 그대로 보존했다. [manifest.json](manifest.json)은 각 파일의 크기·SHA·실제 이미지 해상도를 기록한다. 가변 해상도에 맞춰 [새 탭 뷰어](../../previews/kitchen-full-flow-20261104.html)에서 한 장씩 확대한다. 공개 주소와 실제 표시 결과는 게시 후 추가한다.
