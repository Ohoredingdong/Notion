# MUSE: 실제 이미지 생성 서버 배포

GitHub Pages의 화보 페이지는 정적 호스팅입니다. 사진 정리·배치·제작자료 저장은 동작하지만 Node 서버를 실행하지 않으므로 그 주소에 파일을 올리는 것만으로 화보가 생성되지는 않습니다.

이 구성은 **같은 웹서비스에서 화보 페이지와 이미지 생성 API를 함께 실행**합니다. 서버의 비밀번호 세션으로 API를 보호하며 이미지 API 키를 브라우저에 전달하지 않습니다. 기존 금융 위젯·수집 작업은 이 서버에 복사하지 않습니다.

## 배포하기

이 저장소의 `main`에 `render.yaml`과 관련 서버 파일이 반영된 뒤 [Render에서 배포 구성 열기](https://render.com/deploy?repo=https%3A%2F%2Fgithub.com%2FOhoredingdong%2FNotion)를 사용할 수 있습니다. 배포 화면에서 저장소와 `main` 브랜치, `muse-editorial-studio` 서비스를 확인합니다. 별도 `branch` URL 매개변수에 의존하지 않으며 브랜치는 Blueprint에 명시되어 있습니다.

Render 계정에서 다음 두 값을 **환경 변수 입력란에 직접** 입력합니다. 키나 비밀번호를 채팅·GitHub 코드·화면 캡처에 넣지 않습니다.

| 이름 | 입력할 값 |
| --- | --- |
| `STUDIO_IMAGE_API_KEY` | 이미지 모델 사용 권한과 결제가 설정된 본인의 OpenAI API 키 |
| `STUDIO_ACCESS_PASSWORD` | 이 개인용 스튜디오에 로그인할 비밀번호. 16자 이상 |

기본값은 Docker 웹서비스의 `free` 플랜을 요청합니다. 실제 무료 플랜 자격·제공 여부·중단 조건은 Render의 배포 화면에서 확인합니다. 다른 유료 플랜으로 바꾸기 전에 요금을 확인합니다. 이 설정은 이미지 API의 생성 비용을 무료로 만들지 않습니다.

배포가 완료되면 Render가 발급한 HTTPS 서비스 주소를 엽니다. 주소는 계정과 서비스에 따라 달라지므로 이 문서에는 존재하지 않는 `onrender.com` 주소를 만들어 적지 않습니다. **화보 제작은 이 새 서비스 주소에서 진행**합니다. 기존 GitHub Pages 주소가 자동으로 생성 서버에 연결되는 구성은 아닙니다.

1. 새 주소에서 스튜디오 비밀번호로 로그인합니다.
2. 얼굴·전신 사진과 무드 시안을 넣습니다.
3. 생성 확인 화면에 표시된 유료 요청 수를 확인한 뒤 생성을 시작합니다. 기준 시트는 1회, 시안 1개당 화보 10회의 이미지 요청입니다.
4. 완료된 이미지는 내려받아 보관합니다. 작업과 결과는 서버 메모리에 잠시만 남으며 재시작·유휴 중지 후 사라질 수 있습니다.

`/healthz`는 서버 기동 확인용입니다. 건강 검사 성공과 키 존재 표시는 이미지 제공자의 실제 인증·모델 권한·과금 가능 여부나 생성 품질을 검증한 결과가 아닙니다. 실제 생성 품질·비용은 사용자가 승인한 소량의 유료 생성으로 별도로 확인해야 합니다.

`STUDIO_DAILY_IMAGE_LIMIT`의 기본값은 50입니다. UTC 날짜별로 제출한 이미지 수를 작업 시작 전에 예약하며, 취소·실패한 제출도 보수적으로 포함합니다. 이 수치는 서버 메모리에 있어 재시작하면 초기화되므로 영구적인 결제 한도는 아닙니다. 실제 지출 한도는 이미지 제공자의 프로젝트 설정에서도 관리해야 합니다. 업로드와 결과 역시 임시 메모리에 보관되므로 재시작·서비스 절전 전에 결과를 내려받아주세요.

## Docker로 직접 실행하기

저장소 루트에서 다음 이미지를 빌드합니다.

```sh
docker build -f services/editorial-studio/Dockerfile -t muse-studio:local .
```

실행 환경의 보안 설정에서 두 비밀 환경 변수를 설정한 뒤 이름만 전달합니다. 명령줄에 키·비밀번호 값을 직접 적지 않습니다.

```sh
docker run --rm -p 10000:10000 \
  -e STUDIO_IMAGE_API_KEY -e STUDIO_ACCESS_PASSWORD \
  muse-studio:local
```

공개 배포는 HTTPS 프록시 뒤에서 실행합니다. 컨테이너의 운영 세션 쿠키는 `Secure`이므로 일반 HTTP 개발 주소를 운영 로그인 검증으로 오해하지 않습니다. 로컬 기능 검사는 기존 개발 서버와 테스트 절차를 사용합니다.

## 자동 배포와 확인 범위

Blueprint의 `autoDeploy: false`는 Render의 자동 코드 배포를 비활성화합니다. 검사를 통과한 커밋을 확인한 뒤 Render에서 수동 배포합니다. GitHub Pages나 금융 데이터 writer의 설정은 바꾸지 않습니다.

이 파일과 Dockerfile은 배포할 수 있는 구성을 제공합니다. Render 계정 연결·보안 값 입력·실제 서비스 생성은 계정 소유자가 완료해야 합니다. 이 문서의 존재만으로 외부 서버가 배포됐거나 실제 화보가 생성됐다고 보고하지 않습니다.
