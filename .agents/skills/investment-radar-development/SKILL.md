# 투자 레이더 개발·검증

루트 [AGENTS.md](../../../AGENTS.md), [개발 절차](../../../docs/DEVELOPMENT.md), [환경 감사](../../../docs/DEVELOPMENT_AUDIT_2026-11-05.md)를 따른다. UI 변경은 [일반 위젯 스킬](../notion-widget-development/SKILL.md)도 적용한다. 스킬이 처음 적용되는 대화에서는 사용 사실을 짧게 알린다.

## 1. 운영 기준과 의존 관계

- 기존 체크아웃에서 git 상태·작업 브랜치·정확한 기준 SHA를 확인한다. 원격 main은 데이터 작업으로 계속 바뀔 수 있으므로 조사와 실행에 사용한 SHA를 구분한다. 명시적 요청 없이 worktree를 만들지 않는다.
- `stock-value-radar.html`이 실제로 로드하는 자산·데이터와 관련 수집/생성/게시 스크립트를 먼저 추적한다. v7/v8/v9 등 파일명이나 과거 문서만 보고 현재 활성 화면을 판단하지 않는다. `assets/`의 보존된 모듈과 현재 진입점을 구분한다.
- `.github/workflows/`에서 변경 대상의 schedule·push·workflow_run 연결, 쓰기 권한, main 게시·경합 처리·검증 순서를 확인한다. 레이더 외 금융 위젯의 공용 게시 코드가 영향받는지도 조사한다.
- [README](../../../README.md)의 실행 주소와 앱 구분을 유지한다. 투자 레이더, 기업 노트, 모의투자 학습·보유/관심 기록을 임의 통합하지 않는다. 현재 소스의 저장 키를 확인하고 기존 기록 원문을 보존한다.

## 2. 금융 자료의 의미와 실패 처리

- 가격의 관측 시각, 공시 발행일/대상 기간, 수집 시각, 분석 생성 시각을 구분한다. 새 화면 로드나 새 `generated_at`을 최신 원자료의 증거로 사용하지 않는다.
- 공식/비공식, 원자료 대조 여부, 기간·수치 차이, stale·누락·요청 실패를 유지한다. 알 수 없는 수치를 0이나 임시 가격으로 대체하거나, 자료 오류를 '매수 후보 없음'이라는 정상 결과로 감추지 않는다.
- 성공·실패·부분 갱신·최종 정상 자료 보존을 검증한다. 수집 실패 시 기존 자료를 보존하는 계약을 확인하고, 경고·상태가 화면과 JSON에서 함께 전달되는지 확인한다.
- 결정적 UI 검사는 격리 브라우저에서 체크아웃의 수집 스냅샷을 사용하고 시계를 그 자료에 맞춰 고정할 수 있다. 이는 그 기준 자료의 화면 검증이다. stale/failure 테스트의 시간·응답 주입과 실제 공개 시장 자료 대조를 별도로 표시한다. 테스트용 응답을 운영 JSON에 저장하지 않는다.
- 인증키 존재·인증 성공과 기업별 공식 검증 성공을 구분한다. 비밀키나 실제 개인 데이터를 코드·로그·공개 자료에 포함하지 않는다.

## 3. 구현과 테스트

```bash
python scripts/dev_check.py --suite radar --plan --output /tmp/notion-radar-check
python scripts/dev_check.py --suite radar --output /tmp/notion-radar-check
```

변경 관련 검사 선택은 `--base origin/main`, 저장소 전체 검토는 `--all`을 사용할 수 있다. 실제 옵션·의존성·검사 목록은 개발 문서와 runner의 계획 출력으로 확인한다. 테스트·스크린샷·브라우저/의존성 캐시는 체크아웃 밖에 둔다.

- 기존 테스트를 우선 사용하고 현재 활성 진입점·데이터 계약과의 차이를 확인한다. 오래된 테스트를 위해 후보 수·판정·실제 자료를 임의 변경하지 않는다.
- 변경 범위에 맞춰 검색·필터·페이지·회사 상세/뒤로·근거와 위험·출처 링크·관심 저장/복원·날짜·데이터 로드 실패/누락을 실제로 검사한다. 추천·판정 로직은 공식 대조·기간·누락 상태가 보수적으로 유지되는지도 확인한다.
- 자동화/게시 변경은 지정 파일만 게시, 다른 파일 보존, 최신 자료 덮어쓰기 방지, 경합 재시도와 오류 시 게시 중단을 검증한다. 로컬 임시 Git 저장소나 fixture를 사용하고 실제 원격 main 게시를 QA로 실행하지 않는다.
- 실패는 기준 SHA·입력/명령·재현·원인·수정·재검사로 기록한다. 테스트 제거·필수 검사 skip·빈 성공 출력으로 해결하지 않는다. 기존 실패나 외부 제공처 접근 제한이 남으면 그 이후 미실행 경로도 명시한다.

## 4. 화면·PR·배포 경계

UI 변경 전후를 같은 스냅샷·고정 시간·상태·뷰포트에서 비교한다. 데스크톱·모바일390/320px·작은 iframe을 확인하며 로딩/정상/지연/오류 상태와 주요 조작을 포함한다. 과도한 글자·장식보다 iOS 스타일의 명료한 위계를 사용하되 확정된 시안을 우선한다.

최종 결과는 정확한 커밋의 테스트·브라우저 증거와 함께 PR로 준비한다. 기존 금융 데이터 갱신을 멈추거나 schedule·workflow_run을 임의 끊지 않는다. 데이터 봇의 main 직접 게시와 충돌하는 일괄 브랜치 보호·필수 PR 정책을 승인 없이 적용하지 않는다. 기존 수집 자동화의 권한은 개발 변경의 배포 승인이 아니다. 병합·실제 배포·운영 정책 변경은 사용자 승인 후 진행한다.

배포 전에는 해당 대상 SHA의 필수 검사 통과와 사용자 승인을 확인한다. 다른 커밋의 성공, 필수 검사 누락·실패, 미실행을 성공으로 취급하지 않는다.
